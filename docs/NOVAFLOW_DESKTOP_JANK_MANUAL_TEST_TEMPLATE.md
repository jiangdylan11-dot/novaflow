# NovaFlow Desktop Jank Manual Test Template

## 目的

P4B 已确认自动化环境下 OS/Computer Use 点击不能稳定产生真实 DOM pointer/click marker，rAF 在自动化/遮挡状态下也不可靠。因此本模板用于暂停 P4 自动化采样，转向真实前景窗口下的人工体感记录。

本轮不继续加 probe，不继续优化，不基于不稳定自动化点击做性能结论。

## 测试前准备

1. 确认当前 Desktop 使用 P4B 之后的构建。
2. 关闭会遮挡 NovaFlow 的系统弹框、文件选择框、浏览器窗口和调试窗口。
3. 保持 NovaFlow Desktop 为前景窗口，不要让 Codex、Chrome、资源管理器或聊天窗口覆盖它。
4. 如需看控制台，只在每条测试结束后检查，不要在点击路径中切换焦点。
5. 每条记录只测试一个路径，不要把多个入口往返混在同一条记录里。

## 如何打开 Desktop 前景窗口

1. 打开 NovaFlow Desktop。
2. 点击任务栏中的 NovaFlow 图标，确认窗口处于前景。
3. 如果曾打开系统文件选择框，先关闭它。
4. 最大化或固定窗口尺寸，避免每条测试的布局条件不同。
5. 测试过程中只使用真实鼠标点击 NovaFlow 窗口。

## 测试原则

- 每次只测试一个路径。
- 每条路径从一个稳定页面开始。
- 点击后等待 2-3 秒，再判断卡顿表现。
- 不用追求自动化，优先记录真实体感。
- 建议至少记录 10 条真实操作。
- 如果同一路径没有稳定复现，不要进入优化。

## 字段说明

- 时间：记录真实操作时间，例如 `2026-06-30 15:20`。
- 路径：只写一个路径，例如 `动画 -> 特效`、`特效 -> 动画`、`动画 -> AI序列`、`AI序列 -> 骨骼`。
- 体感卡顿等级：使用 0-5，不要写模糊描述代替分数。
- 卡顿发生点：优先选择点击瞬间、页面切换中、切换后 1 秒、弹框打开、预览刷新。
- 白屏/闪图/按钮失控/布局残留：记录是否出现视觉或交互异常。
- 控制台 error：只记录是否出现 error；具体 error 可放在备注里。
- 稳定复现：同一路径多次出现同类卡顿才写是。
- 复现步骤：写最短可复现步骤，不要混入无关操作。

## 进入 P4C 的条件

只有当同一路径出现 3 次以上稳定卡顿，才开新的 P4C 专项。

不再基于不稳定自动化点击继续优化。P4C 必须围绕人工记录中稳定复现的具体路径展开，并先补足对应路径的观测方案。
