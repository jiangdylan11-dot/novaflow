# 抠图验收基准审计

## 已确认

1. 用户图 3“基本已经可以用了，只是白边”的认可对象，是 `logs/divinepower-matting-study/temporal-refine` 的连续过渡优化离线样片。其后“暂时收尾”的对象是 `contour-refine` 轮廓优化离线样片。两者当时都明确记录程序代码未修改，不能当作已落入程序的画质版本。
2. 离线样片使用独立中性投影层、既有主体信息及该素材的局部薄纱区域。当前程序绿幕路径未复现这套处理。对同一 DivinePower 原片第 0、54 帧，使用当前模块和相同背景合成，能复现青色投影和薄纱退化。不能用当前 Gloweyes 与不同原片的旧样片比较来代替这项同帧核对。
3. 上次四段验收的测试夹具按 `representativeTimelineFrameIndex` 选择 ffmpeg 序列对应的缓存 AI 遮罩。但 Chromium 在部分边界时间实际取得前一帧。此次 Scatter 73 帧中 48 帧的实际图像与该名义编号不相同。例如导出索引 32 的图像来自 RGB 序列 31，却配了遮罩 32，导致飘带外侧黑背景被保留。
4. 将缓存遮罩与实际提交给 AI 的 RGB 匹配后，未修改生产抠图算法，重新执行真实 React 导出 73 帧，截图中的粗黑轮廓消失。第 32 帧的原错误结果和校正结果见 `scatter-matched-32.png`，整段见 `Scatter_遮罩错配校正_对比.mp4`。

## 本轮改动及限制

- 只修正缓存遮罩测试夹具，并记录每帧实际画面匹配结果。必须提供实际 RGB 数据与缓存遮罩对应的源帧；无法匹配时失败，禁止凭名义编号猜测。
- 上次 `docs/cutout-review-current-20260913/index.html` 已标注撤销验收用途，旧媒体和 ZIP 保留追溯，不再作为质量通过证据。
- 当前生产抠图代码未改；雅典娜仍未达到认可样片质量；未打包新安装包。
- Scatter 的上述结论针对上次提供的测试结果。真实 AI 服务接收实际捕获的 RGB，不能由测试夹具错配直接推断安装版 AI 服务也以同样方式错帧。
- 在恢复用户认可效果之前，不能把当前绿/蓝幕模块“回到本轮开始”称作恢复了认可版本。后续必须使用相同原片、相同画面、相同背景与实际 PNG 导出交叉验收四段视频。

## 证据

- `manifest.json`：认可 RGBA 原件与当前模块 SHA256；仅生成同帧对照，不修改原件。
- `athena-0-white.png`、`athena-0-scene.png`：同原片同帧，左为认可离线样片，右为当前模块。
- `matched/frame-matches.json`：73 帧实际 RGB 匹配；最高缩略 RGB 平均差 1.598/255。
- `matched/report.json`：73 帧实际 React 导出，无稳定阶段错误；缓存 AI 遮罩回放，不是新 AI 推理。
- 旧认可视频原件：`logs/divinepower-matting-study/temporal-refine/DivinePower_连续过渡优化_背景预览.mp4`。

验收标准固定为：主体边缘不新增黑/绿轮廓，薄纱连续渐变，保留投影时中性且不被删除，光效颜色与透明过渡保持。不再仅凭程序测试通过或单段样片判断可发布。
