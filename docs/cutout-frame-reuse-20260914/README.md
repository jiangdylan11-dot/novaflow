# 播放缓存复用与连续抠图修复

2026-09-14，版本保持 2.3.214。

## 行为变化

- 播放预渲染建立原尺寸结果，使用无损 RGBA deflate 缓存；预览显示再缩放。保存、PNG 导出复用相同素材、参数、尺寸、帧号的结果。
- 压缩缓存上限 192 MiB / 300 帧；换素材、编辑失效或被容量上限淘汰的帧仍需计算。保存仍有解压、编码和写盘时间。
- 切换素材清除旧任务、RGB 和结果缓存；抠图启用状态仍在但没有当前素材蒙版时重新识别，修复第二个素材空画布分支。
- 取帧或识别失败时退出空白抠图画布、恢复原视频并显示错误；保留严格帧对应检查，不把旧帧当作成功结果。
- 减少合成循环的临时数组分配与无效阴影运算，未修改模型、质量阈值或导出分辨率。

## 实测

同一台机器，1080×1920、24 fps、121 帧素材。Electron 测试装载实际 React 抠图组件、渲染器、保存协调器及主进程编码处理器；识别阶段回放已有真实模型蒙版，**不代表本轮加快了 AI 模型推理**。

| 阶段 | 原流程 | 新流程 |
| --- | ---: | ---: |
| 首次播放预渲染 | 14.7 秒 | 85.5 秒 |
| 预渲染后 PNG 导出 | 105.8 秒 | 6.5 秒 |
| 导出时重新合成 | 121 帧 | 0 帧 |
| 播放预渲染与导出合计 | 120.5 秒 | 92.0 秒 |

首次播放承担原尺寸计算，单次首次播放明显变慢；本轮收益是避免保存和导出再次计算。该取舍适合播放后保存/导出路径，不能表述成所有操作都变快。

完整保存测试：预渲染后「保存并关闭」25.5 秒，其中视频编码 18.0 秒，重新合成为 0。随后切换不同文件 URL 和 video 节点，第二次识别和第 29 帧预览正常；画布有 430050 个非透明像素，尺寸和位置校验通过。该连续素材测试使用同内容的两个文件，尚非用户原始第二个 117 帧素材复现。

证据目录：`logs/cutout-performance-round2/`，包括 `play-before/report.json`、`play-after-2/report.json`、`save-and-next/report.json`、`failure-recovery/report.json`。
