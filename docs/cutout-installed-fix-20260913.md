# 安装后抠图背景与控件修复

用户反馈 Gloweyes 部分帧有暗青色背景残留，且开启“光效透明保留”时旧滑条仍显示。

## 原因与修改

- 已核对安装目录 `C:/Program Files/NovaFlowPortable`：包内脚本与上次打包源码哈希一致，问题确实存在于交付版本。
- 桌面布局函数 `styleAiAnimationCutoutParameterLayout` 给滑条行写入 `display:grid!important`，覆盖了组件的隐藏样式。现在自动模式直接不渲染整个旧参数容器；手动模式仍可使用这些参数，笔刷与羽化作为独立区域继续保留。
- 移除“已识别绿底”和其他幕布识别帮助文字。光效透明保留默认开启，保存的用户开关选择继续有效。
- Gloweyes 第 54 帧上下补边为约 `(0,212,11)`，视频画面两侧为约 `(0,207,21)` 至 `(0,210,22)`。原算法使用全帧单一底色，导致矩形区域残留。现在根据两侧采样估计各行底色，适用于绿幕与蓝幕，排除明显偏离幕布的边缘采样。
- 蓝幕金树有 7 帧因粒子覆盖部分边缘而没达到原来的 85% 底色一致率。保留幕布颜色及一致性检查，将所需一致样本比例改为三分之二，使这些帧继续使用透明光效处理。

## 证据

- 同一实际 JS 算法处理四段主测视频和 DivinePower 回归，共 457 帧；全部识别到相应纯色幕布，没有原来透明区域突然变为不透明的情况。抽查了黑底合成以及光效峰值。
- 使用真实 Gloweyes MP4，经 Electron 视频解码、实际抠图组件和 PNG 导出链路，完整导出 121 帧。分割 IPC 回放此前真实模型产生的遮罩，本轮没有重新运行分割模型。
- 加载当前桌面的真实样式和参数布局函数后，默认开启及手动切回自动时，旧参数容器不存在、识别说明不存在，笔刷大小与羽化均可见。独立投影开关、状态持久化、预览与 PNG 导出的透明度一致性通过。
- 实际视频笔刷验证：擦除改变 16905 个像素，其中 13453 个具有羽化过渡；修复恢复 16800 个像素。
- 25 项专项测试通过，包括绿／蓝补边底色变化不影响主体和光效，以及粒子触及单侧边缘时保持幕布识别。
- 证据目录：`logs/cutout-installed-fix-20260913`。`actual-export-frame54.png` 是本次视频组件真正导出的第 54 帧在黑底与浅底上的合成；该组结果没有使用此前的离线 Python 去绿结果。

重新打包保持版本 2.3.214。安装包文件核验、运行副本同步检查与 4783 在线入口检查分别记录；安装包检查通过不代表在线入口或用户安装验收已通过。本轮不修改正在运行的已安装软件。
