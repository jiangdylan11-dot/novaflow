# 抠图重开、空白预览与画面拉伸修复

这次修复沿用现有抠图参数和光效、投影规则，不重新调整已经验收的效果。

## 复现与原因

1. 自动模式移除旧参数面板后，`hasAiSequenceCutoutNativeDetailReady` 仍检查旧面板及按钮的后代控件。新的光效、投影开关是直接兄弟按钮，检测不到它们。关闭后退出逐帧模式，笔刷面板也不显示，再次打开时状态收尾无法确认进入编辑。画布于是可能使用普通预览布局，出现拉伸、偏移和按钮状态不一致。测试实际 React 控件树：修复前 `nativeReady=false`，修复后为 `true`。
2. 蓝幕算法通过 `{...frame}` 交换蓝绿通道。浏览器原生 `ImageData` 的宽高是原型访问器，展开后丢失，生成长度为零的 alpha。离线普通对象测试未覆盖该差异。现在显式传递宽高。蓝幕原视频首帧修复前输出全透明，修复后有 62525 个非零 alpha 像素；末帧有 203909 个。
3. 运行时恢复整段旧样式时，可能覆盖 React 已经更新的显示状态、宽高和变换。现在在恢复快照后核对当前 React 属性，并把普通视频帧画布纳入恢复。无 React 属性的节点保留原来的恢复方式。几何属性只在恢复快照时处理，不覆盖逐帧播放器持续更新的位置。

- 新增 `cutout-preview-lifecycle-smoke.cjs`：真实 Electron / React 抠图组件、原视频解码、实际运行时样式和关闭函数；检测自动面板、非空透明像素、显示状态、宽高比例、首末帧反复关闭重开以及旧样式恢复。
- 用户的蓝幕金树、MiniMax 企鹅、Gloweyes、Scatter 四段视频各四次开关，共 16 次；首末帧均有可见透明结果，比例正确。
- 在独立 Electron 测试宿主执行真实保存函数与主进程 WEBM 编码处理器，导出蓝幕视频 73 帧并解码 WEBM。测试提供临时文件 IPC 和资源存储适配器，不写用户资源库。
