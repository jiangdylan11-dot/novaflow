# 薄纱连续性与人物绿边修复候选

上一版 material-recovery 已被用户动态验收否决，原因是薄纱透明度／颜色持续变化，人物仍有青绿边。本目录为后续候选，尚未获得用户验收，未制作新安装包。

## 查看方式

打开 index.html。左侧为上一版在相同输入下的结果，右侧为当前程序实际导出的透明 PNG 合成背景；两段雅典娜下排增加薄纱放大区域。五段视频都可连续播放，也可切到 PNG 模式检查黑底、白底、场景与透明棋盘。

序列帧文件在各视频子目录的 frames 中。显示时仅叠加背景，无人工改色或修补。对比左侧仅在捕获 RGB 字节和遮罩文件均相同时复用上一版结果，否则用上一版代码重新计算，避免错帧对比。

## 修复内容

1. 整段视频固定一份由实际画面选出的材质参考。预览、跳帧、重播和导出使用同一参考，不依赖先播放了哪一帧。
2. 根据动作将参考薄纱对应到当前画面。只在匹配可信的区域稳定材质透明度；匹配失败回退单帧求解，避免留下旧姿势的拖影。
3. 只有当前画面相对匹配参考实际增加的光，才参与光色恢复。移除了“其他区域换了一种光效，未变化的薄纱也被重新染色”的处理。
4. 从人物窄轮廓剔除幕布污染及伴随的青色残边；限制透明度只能减少，避免将法杖空隙或背景填成实体。较宽的真实彩色发光区域保留原有光效求解。

这些计算未使用雅典娜固定坐标、文件名或预先指定的特效颜色。验证脚本中的薄纱坐标仅用于比较用户指出的区域，不进入程序算法。

## 验证

- 当前算法 SHA-256：`edfa32dddda866b255eeeda5dab486b7bef99aba0d3f1429213b7d805e3b6d2e`。
- 同一算法完成 Gloweyes 121 帧、DivinePower 117 帧、蓝幕金树 73 帧、MiniMax 73 帧、Scatter 73 帧，共 457 帧实际 React 导出。
- 实际程序记录：Gloweyes 全片使用参考帧索引 0，DivinePower 使用索引 14。这些索引由程序选出，不是脚本硬编码。
- 36 项算法／编码测试通过，包含无关光效不能重染静止薄纱、乱序请求结果一致、移动材质不残留旧轮廓、窄青边修复，以及多色光效、投影开关和笔刷保护。
- 源文件、renderer、解包运行目录同步检查通过。artifact-verification.json 核对五段测试真正执行的算法及 React bundle 与当前文件一致。
- 本轮使用已有真实 AI 遮罩并按实际捕获 RGB 匹配，未再次请求模型推理。夹具启动阶段帧映射尚未注入的报错保存在 startupErrors；实际导出阶段 errors 为空。

连续性检查对源画面变化很小的薄纱区域做动作对齐，再比较输出透明度和灰底颜色变化，记录在 temporal-summary.json。它是回归诊断，不能当作人工透明度真值，也不能代替用户观看连续视频。

本次检查结果：Gloweyes 在这些区域的平均额外透明度变化减少约 16%，DivinePower 减少约 30%；半透明区域的青绿残色诊断量约减半。变化很小的源区域并不等于完全静止，这些数字不表示“闪烁消除百分比”。

另核对 Gloweyes 同一处薄纱：第 1、4 帧原始 RGB 完全相同，上一版 RGBA 分别为 `[207,225,240,134]`、`[202,192,206,145]`；本版两帧均为 `[193,193,231,140]`。见 reported-pixel-check.json。该坐标只是重现用户问题的检查点，未进入算法。

验收页的五段视频加载、时长／尺寸、PNG 黑白／场景／棋盘切换、上下帧和原尺寸显示均通过，错误记录为空，见 gallery-test.json。
