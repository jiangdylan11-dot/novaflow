# H3 编辑能力核验（2026-09-15）

本记录用于回答“模型是否具备所需能力”，不作为 NovaFlow 完整编辑功能的交付验收。用户要求包括主体/物体替换、服装款式与颜色修改、特效主题变化、金币样式变化，以及保留未要求修改的背景和运动。

**核验结论：H3 有这些编辑任务的能力依据，本机也实际执行了服装改色；但当前 beta5 4 步和专用 Ref2VA 20 步两套配置都未通过“只改颜色，其余保持”的测试。现有证据不足以承诺用户整套需求已经可稳定实现，不能仅继续修改提示词后就宣布达标。未对火焰变冰成片作出成功声明，也未进行 H3 与 Kling OMNI 的同素材对照。**

## 官方依据

- MiniMax 官方发布说明将自然语言控制的音视频参考与编辑列为预训练任务，并同时承认上下文理解与部分能力完成度仍有限制：<https://minimaxi.com/blog/minimax-h3>。
- 官方 Ref2VA 指南将人物、动物、物体、服装、背景和视觉特效列为可定义的可见内容，并规定源视频编辑、属性转移与保留关系：<https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md>。
- 官方开源说明：Ref2VA 基模已开放；多阶段理解系统 H3-Context-IR 和 2K 重生成系统未包含在开源发布中，开发者可实现自己的上下文处理系统：<https://github.com/MiniMax-AI/MiniMax-H3>。
- 当前 NovaFlow 默认权重是第三方 `10Eros_Max_h3_TURBO-hybrid_beta5_int8.safetensors`，不是未修改的专用 Ref2VA。其作者建议 `res_multistep/simple` 使用 6–8 步；当前程序默认 4 步。作者也指出参考场景不应使用额外缓存加速。该差异是待对照变量，不能直接归因全部失败：<https://huggingface.co/TenStrip/10Eros-Max?not-for-all-audiences=true>。

上述证据支持 H3 具有这类编辑任务能力，不证明任意输入都可达到 OMNI 的同等效果，也不证明 NovaFlow 当前流程已达标。尤其不能把“特效可以作为 Subject”单独当作“本地火焰变冰已经验证”的证据。

## AI 助手独立核验

Grok 实际接收了各源视频 7 张带时间戳画面，使用普通中文原句。以下只检查提示词含义，不证明生成效果：

| 输入 | 实际结果 |
| --- | --- |
| 白裙改红，款式、人物、动作、背景不变 | 一次调用返回对应编辑和保留关系；通过前端。 |
| 换深蓝牛仔外套与长裤，脸、头发、动作、背景不变 | 一次调用理解正确；原前端动作关键词校验误拒绝。修正后同一原始响应复验通过，没有重新调用云端。 |
| 金币树和金币粒子变冰晶主题，保留路径节奏及背景 | 一次调用返回冰晶材质、结构及粒子替换关系；通过前端。尚未作为成片验收。 |

本地助手的两种金币表述已实际调用并通过格式及双语恢复，但长句结果仍出现“金币的旋转样式”等不准确措辞，主体保留项也不够清楚；这不能算语义优化已经完成。通用换装/特效本地优化仍待实测。原报错主要包括模型返回的关系字段缺省、等价标签、重复主体定义、未用音频空字段、前端动作/镜头词表误拒绝。格式容错修复不等于提示词语义或模型成片一定正确。
