# Export Blocking Overlay Layer Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the existing shared EditorApp export-blocking overlay visibly cover the export modal and prevent repeated interaction while export work is running.

**Architecture:** Keep `exportBlocking` as the single lifecycle owner. Mark and raise its root in the authoritative locked bundle source asset, then add one marker-specific compatibility guard to the source Runtime so the generic full-screen modal scanner cannot overwrite the overlay z-index with `!important`. Use the existing Runtime sync chain to publish byte-identical renderer mirrors.

**Tech Stack:** Minified React renderer bundle, Node.js contract checks, Electron locked `4783` renderer mirrors, PowerShell validation.

## Global Constraints

- Modify only the existing shared EditorApp export-blocking presentation; do not change export workflows, IPC, PNG generation, Spine output, video encoding, AI workflows, Preview, or Resource state.
- Do not change `MODAL_LAYER_Z_INDEX`; the only Runtime change is one exact `data-novaflow-export-blocking` classifier exclusion.
- Runtime code added: 1 compatibility-guard line; no Runtime business logic.
- The export-blocking overlay must remain below the boot splash maximum layer `2147483647` and above the export notice layer `2147483644`.
- Update `particle-editor/assets/index-BbIa-2NM.js` and `particle-editor/novaflow-brand-runtime.js`; publish renderer and `dist/win-unpacked` mirrors through `npm run sync:runtime`.
- Append the required bug-fix record to `logs/debug.log`.
- Finish with the mandated checks, `npm run auto-commit`, and a clean working tree.
