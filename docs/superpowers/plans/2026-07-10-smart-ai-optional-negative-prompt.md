# Smart AI Optional Negative Prompt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Smart AI generate and write a negative prompt only when the active page has a negative prompt control.

**Architecture:** The renderer sends an explicit `supportsNegativePrompt` capability derived from the active DOM. The admin server defaults the capability to enabled for backward compatibility and uses it to select output instructions and normalize provider results.

**Tech Stack:** Browser JavaScript, Electron IPC, Node.js admin server, static contract tests, PowerShell/npm verification.

## Global Constraints

- Do not route by model or provider name.
- Do not change Smart AI dialog layout or generation workflows.
- Existing pages with a negative prompt control must retain two-field behavior.
- Modify source files only, then run `npm run sync:runtime`.
- Append `logs/debug.log`, run required checks, and finish with `npm run auto-commit` and a clean working tree.
