# Split Inpaint NSFW Toggle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a default-off NSFW switch to the split editor's local-edit and smart-completion toolbar so enabled runs use `Qwen-Rapid-AIO-NSFW-v20.safetensors`, while disabled and removal runs keep their current workflows unchanged.

**Architecture:** Put the tested Rapid AIO ComfyUI graph in a standalone `split-inpaint-nsfw.workflow.js` module. Keep `spine-split-runtime.js` as dispatcher/state glue: expose the switch only for `edit` and `completion`, resolve an explicit NSFW route, validate the live Runtime, and dispatch to the module. Preserve current crop/mask preprocessing, validation, RMBG, and hard-mask pasteback.

**Tech Stack:** Browser JavaScript Runtime shell, ComfyUI `/object_info` and `/prompt`, Node.js `node:test` contract tests, NovaFlow runtime sync/check scripts.

## Global Constraints

- Modify source files under `particle-editor` and sync scripts only; never directly edit renderer or win-unpacked mirrors.
- The switch is visible only in local edit and smart completion, defaults OFF on each new entry, is disabled while busy, persists through a failed retry, and resets after success or exit.
- OFF keeps `qwen-edit-v5` and `qwen-completion-v4`; removal always keeps `removal-v4` and never exposes the switch.
- ON must use the exact checkpoint `Qwen-Rapid-AIO-NSFW-v20.safetensors`; if unavailable, show a clear Runtime/model error and do not silently fall back.
- Keep existing edit/completion preprocessing and hard-mask pasteback so unmasked pixels remain protected.
- Add only dispatcher/bridge code to `spine-split-runtime.js`; the complete Comfy workflow belongs in the new module.
- Append `logs/debug.log`, run runtime sync/check/entry validation, then use `npm run auto-commit` and finish with a clean working tree.

## 需求理解

局部编辑与智能补图需要一个成人内容模型选项。用户主动打开 NSFW 后，两种模式都走已在当前 8188 Runtime 实跑成功的 Rapid AIO checkpoint；默认关闭时完全沿用现有模型。去除物体不在范围内。

## 目标效果

- 顶部 `退出` 右侧显示紧凑 `NSFW` 开关，仅在局部编辑/智能补图模式出现。
- 新进入工具时开关为 OFF；ON/OFF 状态清晰可辨且忙碌时不可操作。
- ON 的局部编辑与智能补图均能成功提交并产出图像。
- 成功后或退出工具后复位 OFF；失败后保持 ON 便于重试。

## 初步根因

当前局部编辑和智能补图路由固定映射到 Qwen Edit V5 / Completion V4，没有用户可控的模型策略字段；Rapid AIO 虽已在其他功能使用且本次预飞成功，但没有针对遮罩局部编辑封装成独立工作流，也没有接入选择工具状态。

## 推荐方案

用显式布尔状态选择显式路由，NSFW 路由再调用独立模块生成经过预飞的工作流图。继续复用现有上传、等待、裁切、遮罩和回贴链路。这是最小影响方案，也满足 V2.5 Runtime 单纯调度的要求。

## 风险分析

- 功能风险：模型或节点缺失会失败；通过 `/object_info` 精确校验并禁止静默回退。
- UI 风险：顶部空间有限；使用紧凑开关、仅在两种相关模式显示并允许工具栏换行。
- 性能风险：约 26.48 GiB checkpoint 首次加载较慢且占用显存；禁用并发点击，沿用 busy 状态。
- 状态同步风险：模式切换或失败可能错误复位；以测试固定“新入口/退出/成功复位、失败保留”。
- 回归风险：路由条件若过宽可能影响 removal；测试明确断言 removal 永远不接受 NSFW provider。

## 工作量评估

中等改动：一个独立 workflow 模块、两个聚焦测试、Runtime 少量胶水、加载/同步清单更新。预计 Runtime 新增少于 100 行，不触发 Runtime 业务扩张。
