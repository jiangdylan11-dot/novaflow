# UI 设计质量诊断与实施顺序

用户要求是：用布局或 UI 参考图、风格参考图、人物物品素材和简短需求，生成完整的新设计或风格迁移。没有明确要求改变布局时，沿用原功能分布。界面继续使用现有绘图排版，内部处理自动完成，不增加模式、助手弹窗和人工流程。

## 当前结论

正式生成链尚未达到用户要求。不能用主题改变、布局部分保持、提示词合同检查或构建通过代替成品质量验收。先前包及后台修复了请求规则，不等于解决了高质量 UI 设计。

当前前端整理用户需求，Grok 输出五段 UI 方案，最终仍由生成模型整图编辑。实际 Qwen 参考节点提供图像条件和匹配尺寸的空 latent，不提供确定的区域或网格锁定。要求全部重新设计和保持结构同时成立时，单靠文本不能保证执行结果。

发现 GPT 参考图模式的共享初始质量是 low；这可能影响云端成品质量，但本轮没有完成 GPT/Google 正式出图，不能将本地失败泛化到云端，也不能以独立图像工具的成功代替它们的验收。正式质量参数调整应与费用估算保持一致。

## 实施顺序

1. **先验证生成能力。** 固定同一布局参考和需求，分别实测正式本地、GPT、Google 路径。覆盖新主题与风格迁移，记录实际质量档、尺寸、参考输入、费用和结果。独立工具仅用来展示可评估的目标；未经实测不能宣称正式模型都支持同样质量，也不能静默更换用户选择的模型。
2. **让内部助手形成具体设计决策。** 确认每张图提供布局、视觉语言还是素材；保留用户的限制。把风格落实到造型比例、轮廓、色彩层级、材质、光影和组件语言，把新主题落实到完整人物、环境、符号家族和控件。避免当前“全部金色石纹”的同质化描述。模型看不清的位置或数量不能猜成模板。用户不需要学习这些内部字段。
3. **验证结构与内容约束的可执行方式。** 自建布局直接使用真实坐标；完整 UI 参考需内部识别并验证功能区域、网格与文字。优先检验模型原生参考编辑。如果原生编辑仍无法稳定满足硬约束，再验证区域生成及组合，让程序控制位置和数量、重复符号复用同一资产、文字用真实字体排版；保留设计组件的自由轮廓，不把布局矩形作为美术边框。
4. **按成品验收再集成。** 检查区域遗漏、行列、文案、重复资产一致性、主题残留、视觉层级和细节。自动检查只承担可测项，商业美术完成度需要看图评估。重试须有明确次数和费用边界，不以自动无限重绘增加成本。结果满足同一参考下不同主题/不同画风的实际验收后，才接入正式 UI 的生成按钮和交付包。

不把多阶段生成直接定为必须方案；先用实际结果选择能满足质量、结构、速度和成本的最小流程。本轮只新增诊断记录与隔离对照，不发布新的“已修复”版本。
