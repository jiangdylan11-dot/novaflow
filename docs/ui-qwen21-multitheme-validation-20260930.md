# Qwen 2.1 UI 多主题与材质验证

## 范围与当前结论

按用户要求先处理 Qwen 2.1。绘图/UI 外观、侧栏、按钮、提示词排列不改变，不新增主题模板或选项；GPT/Google 生图流程未改版。

已实现内部 UI 规划合同：布局修改范围与视觉修改范围分别判断。支持保持布局、只改指定区域、明确重新排版和无布局来源的新设计。布局图、风格图、内容图与人物物品素材分工；实际生成输入将布局图排在第一位，同步映射图号。用户原提示词仍保留在编辑器，不写回内部美术方案。

局部调整必须包含修改项和保留项，避免“人物缩小/按钮上移”被整体锁定否定，或被扩展成全页重排。无有效布局来源时不从纯风格/素材图继承布局。模型返回合同缺项时停止提交，避免退回绘图模板。

云端规划响应、后台管理响应、本地助手 Worker 请求与 Python 推理返回均传递同一合同。保护引用标识、过滤模块内部名称；绘图和旧云端生图路径保持原行为。

**执行合同和调用链检查通过，不等于成品质量通过。本机这一套 Qwen 2.1 配置的整图编辑尚不能稳定达到用户要求，不应作为质量达标版本发布。**

## 用户反馈：配色偏素、缺乏质感

内部美术规划已要求从风格参考具体提取主色、强调色、明暗层级、边缘、反光和体积；布局参考仅继承几何与功能，不保留原人物装备/符号外形。要求质感时区分金属、宝石、哑光与柔软材料，避免同色同亮度；仍尊重淡彩、扁平和简约需求，不把高饱和作为统一预设。

进一步测试在已有埃及主题图上仅调整配色、材质和灯光，检查“先形成主题，再提升美术”是否能保住已有结构。结果保住了人物和网格，但出现强描边、杂乱背景和过度锐化效果，仍未达到质感目标；不能把提升饱和度当作材质改善。该实验仅用于诊断，未将双次生成接入正式链路。

- 本地 Python UI 合同及无权重推理返回测试：3 项通过；真实本地规划模型推理尚未验证，GPU 图像测试使用 Grok 规划。
- 实际 Worker Qwen 图检查：211 检查通过。
- `sync:runtime`、`check:runtime`、`check:entry` 通过。入口检查含本地助手、启动器、提示词助手及浏览器计算路由。
- 保留现有构建报告的打包素材 `class_type` 扫描提示；不是本次引入。
- 源码及开发运行文件已更新；本次未更新已安装启动助手、未生成发布 ZIP、未部署后台或发布线上网页。线上仍使用原版本。

后续成品质量需要独立约束与验收：先识别区域与网格，再限定编辑范围，文字和功能图标可靠保留/重建，生成后逐区检查。不能用继续加提示词或调高饱和度代替这些环节。
