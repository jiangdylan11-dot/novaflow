# Qwen 2.1 UI 可用设计流程方案

## 交付目标

用户提供布局图、风格图、人物/物品素材与简短需求，得到布局遵循要求、主题完整、风格统一的 UI 设计稿。继续使用现有绘图式界面和左侧可选布局编辑，不增加预设、模式选择、手动优化或验收对话框。GPT/Google 生图暂不改版。

没有自建布局时可以使用完整界面参考；没有布局来源时自动建立布局。只换画风保留内容身份；换主题允许重新设计人物、道具、场景、符号和组件外观；局部改变位置/大小只影响指定区域。模块名称仅供用户识别，模块说明传递用途。

“可用”按结果验收：位置与数量符合要求，主题完整，功能不遗漏，重复符号一致，文字不被改坏，材质与配色符合风格来源。不能将 GPU 出图或合同测试通过等同于成品合格。

## 正式方案：后台自动完成四个阶段

### 1. 建立布局与内容清单

自建布局使用真实坐标；参考布局单独分析，不让风格图参与几何识别。记录区域相对位置、面积、叠放、网格行列、按钮数量、现有文字和符号功能。网格必须数图标中心，不能将提示栏、金额栏、按钮或装饰算为一行。

相同参考图复用识别结果，避免换主题时重复分析。结构不够清楚的部分不猜常见模板。自动分析仍需单独验证：本次试验中行列清点正确，视觉模型估计的区域坐标存在明显错误，因此不能直接把估计坐标当作可靠的合成矩形。

### 2. 制定统一美术方案并按区域生成

将风格图解析为色彩关系、明暗、造型比例、边缘、材质、笔触和光照。它提供美术表现，不提供人物或图标身份。人物/物品素材单独承担身份来源，布局图承担区域与功能。

Qwen 2.1 分别编辑背景、人物、组件、符号等实际需要改变的内容。只换风格时，用原内容作编辑画布，避免整张异主题风格图带入其人物和道具。换主题时为每类内容明确新造型；只改变指定区域时，区域外像素通过合成保持。

一组重复图标先生成每种独立资产，再在原位置复用同一成品；不要求模型一次画满整个阵列并保证每个重复物完全一致。所有资产共用同一美术方案与风格依据，不能各自临时选择色调或材质。透明度、边缘和背景衔接需逐项验证。

### 3. 按布局合成完整设计稿

程序将生成美术放回已确认的区域，确定行列、功能位置和数量。例如原图六列五行，合成固定三十个位置，主题变化不会变成三十六个。

组件外轮廓、描边、装饰、纹样可以自由设计，布局矩形不画进成品。字体、数字、标签和功能图标使用可靠的排版/资产输出，保留未要求修改的文字及含义。模型负责美术，排版与合成负责几何和重复一致性。

这不是把整张生成图拉伸回原尺寸：拉伸不能恢复缺失区域、错误行列或改错的功能文字。

### 4. 校验并修复具体失败区域

结构检查优先使用可确定的数据：区域、行列、数量、文字及资产复用关系。视觉检查判断主题是否完整、是否串入风格参考内容、主体与背景是否分离、材质是否统一及是否有拼接边缘。

只修复失败区域，最多一次自动修复；不要整图重新采样破坏已经合格的部分。修复后再次检查，不合格则明确说明未通过，不能显示质量达标。视觉检查器本身也必须用已知正/反例验收，不因它返回 PASS 就自动视为可靠。

## 实现顺序与完成定义

1. 先固定布局、风格和素材职责，修正原生图号及重复指令；已有初步代码修正。
2. 建立可信区域数据、独立资产与合成原型，先完成当前参考图的埃及、太空、海盗三主题；这部分尚未正式接入。
3. 接入文字与功能保护、结构校验和区域修复；这部分尚未正式接入。
4. 验证只换风格、人物缩小/按钮上移、无布局生成，再覆盖背包、商城、大厅等不同结构。多个种子连续通过后再更新匹配的后台、启动助手和网页，不能用一张好图证明广泛可用。

本次不把模板或多选项引回界面。用户操作继续为添加参考图、写需求、开始生成；布局编辑保持可选。

## 本次已完成的接入修正

- 对齐官方编辑指令：多图使用 `<image1>` 等原生图号，单图使用自然称呼；先描述修改动作，未改部分简短保留，不重复拼接原需求、整套旧外观和保留规则。
- 修复 `preserve` 具体事实被编译器遗漏的问题；结构化传递实际网格行列。
- Grok 规划先单独清点布局图，再独立处理美术需求。两次行列读数不一致时停止提交并清除识别缓存，不将第一遍的错误抄入第二遍作为事实；一致仍不保证生成保持布局。识别结果按完整图片数据缓存，最多保留四条。取消后不继续提交第二阶段请求。
- 纯风格迁移将风格图用于视觉分析，Qwen 编辑输入保留内容/素材图，减少将风格图物品直接复制进原图的机会。生成合同与分析合同分别记录。
- Worker 不再额外拼接与原生编辑指令重复的 UI/Drawing 保留规则；绘图、GPT/Google 生图行为与界面布局保持现状。
- 本地 Python 合同兼容网格字段；真实本地规划模型尚未验收，当前 GPU 验证使用 Grok 规划和本机 Qwen 2.1 出图。

## 真实测试观察

同一海神布局、758×1640、种子72161、40步、CFG1、本机 Q8 GGUF、heretic量化编码器、2.1 VAE。以下为实测，不等于完成四阶段方案。

| 测试 | 结果 | 判定 |
| --- | --- | --- |
| 原生多图短指令 | 材质、体积和色彩明显改善，但受风格图人物/布局影响 | 证明能画出质感，不证明布局可靠 |
| 正式规划后埃及主题 | 新人物、权杖、神庙与符号出现，六列五行；文字及区域比例仍有变化 | 美术有进步，完整验收未通过 |
| 正式规划后太空主题 | 新机器人与空间站，符号仍增加一行 | 未通过 |
| 原多图纯风格迁移 | 混入木乃伊、圣甲虫、安卡等风格图内容 | 未通过；已修正输入策略 |
| 人物缩小并换海盗主题 | 人物缩小，但被风格图带成木乃伊，比例精度未证明 | 未通过 |
| 原图编码采样，denoise0.85 | 保住布局，但只改出银色盔甲，没有完成太空重设计 | 未采用 |
| 单图原生编辑，文字说明渲染表现 | 保留海神与原符号身份，六列五行，材质增强；位置仍有偏移 | 可作为风格迁移方向，尚不能声称精确布局 |
| 单图原生太空重做 | 机器人与星际物品出现，仍增加一行且原武器轮廓残留 | 未通过 |
| 正式纯风格路径，只向 Qwen 传内容图 | 未混入木乃伊，但单独识别器误分阵列、数错一行，成品新增一行 | 未通过；补充独立读数一致性检查，不能直接信任一次识别 |
| 最新正式规划，仅运行识别与规划 | 两次网格读数不一致，一致性检查明确停止；没有提交 GPU 生成 | 错误拦截生效，布局识别可靠性尚未通过 |

验收记录位于忽略目录 `.artifacts/ui-qwen-native-20260930/`、`ui-qwen-formal-native-20260930/`、`ui-qwen-separated-final-20260930/`、`ui-qwen-structural-20260930/`。每次生成保存实际工作流、prompt ID、history 和 PNG；新正式测试记录输入 SHA-256，使用独立上传名，防止测试图片被后一次实验覆盖。

当前证据支持继续使用 2.1 改进流程，不能推出它已经与 GPT/Google 同等稳定，也不能根据本机量化组合的单次失败判断官方模型上限。提高 CFG 或降低去噪强度均未同时解决重设计与布局问题。
