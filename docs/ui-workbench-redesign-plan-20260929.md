# NovaFlow UI 工作台改版计划书

日期：2026-09-29

状态：方案稿；本轮不修改运行代码，不打包、不发布。

## 1. 改版目标

把 UI 版块调整为与现有绘图版块一致的工作方式：用户放入参考图、填写需求，点击一次“生成 UI”；需要自行规划布局时，展开结构生成器，在中央画板编辑布局。

核心输入是“可选布局 + 可选参考图 + 用户需求”。结构生成器保留，但退出必选流程。AI 助手负责理解这些输入并整理生成指令，不再要求用户先完成一组设计分类和风格选择。

本次输出仍然是 UI 视觉设计图。布局块用于控制区域和用途，不意味着生成结果自动成为可编辑的按钮、文字图层或前端代码。

## 2. 当前问题与改动边界

已从本仓库源码确认：

- 生成入口会拒绝没有连接页面结构的任务，也会拒绝没有参与生成区块的结构。
- 中央工作区以节点、端口和连线组织参考图、布局和生成器，增加了开始生成所需的操作。
- 提示词助手除了用户需求，还会构建设计动作、目标风格和质量倾向等约束。只删界面按钮，不能消除这些默认约束。
- 当前存在本地、GPT、Google 的不同生成路径；布局输入和参考数量限制不能通过统一隐藏控件来处理。

改动范围仅为 UI 设计流程及其专用提示词处理。保留现有顶部、左侧主导航、账号与模型接入、资源库和绘图版块行为。延续现有深色面板、绿色主要操作和紧凑控件风格，不重做软件外壳。

## 3. 页面排版

沿用绘图版块的区域分布，中央画板始终占据主要空间。

```text
┌────────────────────── 现有顶部栏 ─────────────────────────┐
│主导航│ 左侧设置           │ 中央画板                  │资源列表│
│      │ 绘图 / UI         │                          │        │
│      │ 模型选择           │ 查看结果 / 编辑布局       │ 原有   │
│      │                  │                          │ 图片   │
│      │ ▸ 结构生成器      │ 布局块直接在这里拖动、缩放 │ 与结果 │
│      │   展开后显示：     │ 点击布局块编辑对应属性     │        │
│      │   添加模块         │                          │        │
│      │   当前模块属性     ├──────────────────────────┤        │
│      │   生成布局参考     │ 尺寸及当前模型参数  生成 UI│        │
│      │                  │ 参考图缩略图条 + 上传      │        │
│      │                  │ 正面提示词 │ 负面提示词   │        │
└──────┴──────────────────┴──────────────────────────┴────────┘
```

上图是区域关系示意，实际宽度、间距和控件样式沿用现有绘图页面。

### 左侧设置

- 保留模型选择。
- 增加一个可展开的“结构生成器”入口，默认收起。
- 展开后显示“添加模块”、选中模块的属性和“生成布局参考”。
- 不放布局缩略预览；中央画板已经承担该职责。
- 不放“角色区域 / 装备区域 / 背包区域”等模块列表；直接点击画板上的模块。
- 未选中模块时，只显示简短操作提示，不展示一整套空属性表。

### 中央画板

- 默认用于查看生成结果或所选资源，不再出现生成器节点、连接端口和连线。
- 展开结构生成器后可进入布局编辑；结果与布局都存在时，提供简洁的“结果 / 布局”切换。
- 编辑布局不覆盖生成结果；查看结果不删除布局草稿。
- 画板可以缩放和适配窗口，但不再承担无限节点流程编排。

### 底部生成区

- 复用绘图式的横向参数栏、参考图条、提示词区和生成按钮。
- 常用参数直接显示；其他参数延续对应模型现有的收纳方式。
- 本地模型的正面、负面提示词左右并排，保留已有编辑、历史等入口；AI 助手放在正面提示词标题旁。
- 不支持负面提示词的模型只显示设计要求，不用空白负面框占空间。
- 所有参考图集中在一条缩略图列表中，不增加固定的“布局槽 / 风格槽 / 人物槽 / 物品槽”。

## 4. 结构生成器

结构生成器的作用是：在软件内制作布局参考，并保留区域用途说明。

操作流程：展开结构生成器 → 添加模块 → 在画板拖动和缩放 → 点击模块编辑属性 → 生成布局参考。

每个模块只维护一份属性：

| 属性 | 用途 |
| --- | --- |
| 名称 | 方便识别当前模块，例如角色展示区 |
| 作用说明 | 描述区域承担的内容和功能 |
| 位置与尺寸 | 与画板拖动、缩放实时同步，允许精确输入 |
| 生成要求 | 描述该区域必须出现或需要避免的内容 |

删除、锁定等已有编辑操作保留在当前模块内，不扩展成新的区域分类系统。

“生成布局参考”后的行为：

1. 在底部参考图条中出现一张布局参考，点击可以返回编辑。
2. 同时保存布局图和模块语义数据。提交时根据模型能力使用图像、结构描述或二者组合。
3. 编辑器边框、选中态、拖动手柄不进入生成输入；模块名称默认是结构说明，只有明确要求的界面文案才作为输出文字。
4. 首次生成后，再修改布局会更新同一份参考，避免生成时误用旧布局，也不重复追加缩略图。
5. 收起结构生成器只收起编辑区，不取消这张布局参考。
6. 从参考条移除布局参考后，它不再参与生成，但布局草稿保留，方便再次使用。
7. 更改输出比例时，按比例映射布局坐标并在画板显示实际效果，避免沿用旧像素坐标导致越界。

没有结构、没有布局参考时，同样允许根据用户需求生成。空白布局草稿也不应阻塞其他有效输入；没有任何需求、有效参考或有效布局时，才提示补充输入。

## 5. 参考图与用户需求的关系

支持以下组合，不要求用户先选择模式：

| 输入 | 预期行为 |
| --- | --- |
| 只有需求文字 | 根据需求组织页面布局和视觉设计 |
| 布局图 + 需求 | 按参考布局完成 UI 设计 |
| 风格图 + 需求 | 参考视觉语言，自行组织合理布局 |
| 布局图 + 风格图 + 人物或物品 | 按布局组织内容，将元素融入参考风格 |
| 自建结构 + 风格图 + 元素 | 以自建结构控制区域分布，参考风格并融合元素 |
| 已有结果 + 修改要求 | 以结果为基础修改指定部分，尽量保持其他内容 |

参考图用途优先依据用户明确说明，例如：“图1是布局，图2只参考按钮和边框风格，图3的人物放左侧。”没有说明时由助手判断，不要求用户再逐图填写一遍角色分类。

输入解释规则：

- 用户明确要求优先；自建布局已启用时，默认由它控制区域分布。
- 风格参考重点提取配色、材质、边框、按钮、图标和层级关系；不要把风格图中的人物、商品和文案自动搬进新设计。
- 人物或物品参考负责指定元素，按需求融入整体设计。
- 同一张图可以承担多种作用，不限制成互斥类别。
- 同一张已有界面也可以用于风格迁移，保留布局与内容，改变视觉语言，无需先手工重画结构。
- 若要求“完全保留布局”和“重新排布”同时存在且无法判断优先级，只提出一个具体问题，不弹出整套设置表。

参考编号、提示词引用和实际提交顺序必须一致。删除参考后，不能把原来的“图2”静默解释成另一张图；使用稳定的引用标识维护关联，无法解析的引用在提交前明确提示。

## 6. AI 助手简化

删除当前助手中的必选设计目标、内容类型、用途分类、质量倾向、固定风格按钮和重复的参考图职责设置。对应的隐藏默认约束也一起移除，避免用户没有选却仍被强制套用。

保留一个简洁的需求输入和必要的参考预览。现有模型服务选择若确有必要，沿用已有设置，不新增一套相同配置。

UI 专用优化应完成：

- 识别布局、风格、指定元素和界面内容的分工。
- 保留明确的区域数量、位置关系、界面文案和人物物品要求。
- 把风格落实到按钮、卡片、面板、图标、排版和背景等部件。
- 根据“全新设计”或“局部修改”的自然语言要求确定修改范围。
- 不因上传了游戏截图就擅自添加金币、战力、角标等未要求内容。
- 区分参考截图中的外部软件工具栏与目标 UI 本身的按钮和文字，不能把所有界面文字都作为噪声删除。

不增加自动评分、多轮重试或风格模板库。本轮先把一次理解、一次生成的链路做好。

## 7. 一键优化并生成

默认流程：收集本次输入快照 → 理解需求并优化 → 生成 UI → 中央显示结果并进入原有资源列表。

用户只点击一次“生成 UI”。过程中显示“理解需求…”和“生成 UI…”两阶段状态，不要求手动复制助手输出。

交互与可靠性规则：

- 保留原始需求；优化后的实际生成指令可以查看，不强制替换用户正在编辑的文字。
- 手动使用 AI 助手后，若相关输入没有变化，生成时复用本次优化，避免重复调用。
- 用户需求、负面要求、参考图、布局语义或影响指令的模型配置变化后，旧优化结果失效。
- 生成任务使用点击时的完整输入快照；处理中发生的新编辑不被迟到的助手结果覆盖。
- 取消优化后不得继续发起生成；取消生成沿用现有中止能力。
- 优化失败时保留输入并显示原因，允许重试，不在用户不知情时跳过优化。
- 理解需求和生成图片的数量上限可能不同。不能只分析前几张图却假装分析了全部；实现前明确各服务能力，超限时给出实际限制。
- 超长需求和模块说明不得被静默截断；需要压缩时保留关键约束，无法完整传递时明确提示。

## 8. 技术落地范围

具体复用方式在实施时结合现有组件确定；以下是已定位的主要改动位置。

| 位置 | 改动内容 |
| --- | --- |
| `novaflow-web/renderer/ui-design.bridge.js` | 取消结构强制前置；组织新工作台；串联优化、取消、生成和结果入库 |
| `novaflow-web/renderer/ui-design.workspace.js` 或新的工作台适配模块 | 以中央布局编辑和结果预览取代节点操作；保留旧项目读取能力 |
| `novaflow-web/renderer/ui-design-generate.tool.js` | 绘图式底部参数栏、参考图条和本地双栏提示词 |
| `novaflow-web/renderer/ui-design.inspector.tool.js` | 仅编辑当前选中模块，不增加模块列表和小布局预览 |
| `novaflow-web/renderer/ui-design.structure.tool.js`、`ui-design.project.resource.js` | 布局语义、参考关联、任务输入和旧项目兼容 |
| `novaflow-web/renderer/ui-design.preview.js` | 资源选择与中央预览、加入参考的交互对接 |
| `novaflow-web/renderer/ui-design-assistant.dialog.js`、`ui-design-assistant.workflow.js` | 精简助手，移除默认分类契约，管理优化结果与失效条件 |
| `novaflow-web/renderer/ui-design-generate.workflow.js` | 正确处理无布局、无参考、混合参考和不同模型输入 |
| 云端与本地提示词服务中的 UI 分支 | 加入 UI 专用解释规则，保持绘图分支行为不变 |

旧节点数据可以作为兼容存储继续存在，但不再要求用户操作连线。旧项目中的布局、参考、生成参数和结果必须可恢复；若旧项目有多套生成方案，不能只保留第一套而丢弃其他内容。

原始需求、优化指令和实际生成参数应关联到对应任务结果，方便回看、复用和排查。

## 9. 实施顺序

1. **先改生成前置条件。** 打通有布局、只有参考、只有文字的调用链；补充针对性验证，确保没有伪造空白布局输入。
2. **再改工作台排版。** 接入现有模型选择、底部生成栏和资源列表，移除节点交互，保留中央大画板。
3. **接入可展开结构生成器。** 完成模块绘制、属性同步、布局参考更新，以及结果和布局之间的切换。
4. **简化并串联助手。** 移除旧选项及隐藏约束，接通单次优化到生成，处理缓存失效、取消和错误。
5. **进行真实流程验收。** 核对旧项目恢复、模型差异、实际出图和绘图版块回归。

不以完成界面截图作为链路完成，也不以构建通过作为设计质量验收。

## 10. 验收标准

| 场景 | 通过条件 |
| --- | --- |
| 纯文字需求 | 不创建结构，不连接节点，可以完成生成 |
| 外部布局 + 风格 + 人物 | 一次点击进入优化和生成，全部有效参考按正确顺序提交 |
| 自建布局 | 画板拖动和属性编辑同步，布局参考更新，不重复追加 |
| 布局编辑收起 | 已启用布局仍参与生成；移除参考后不再参与 |
| 本地模型 | 正负提示词左右并排，实际请求使用对应内容 |
| 更换风格参考 | 同一布局可生成不同视觉方案，重点检查区域分布与指定元素保留情况 |
| 局部修改 | 修改指定区域，检查未指定区域是否出现明显不必要变化 |
| 优化结果复用 | 手动优化后未改输入，不再次调用；改参考或布局后重新优化 |
| 失败与取消 | 优化失败或取消后不发起生成，不覆盖新编辑 |
| 参考编号与超限 | 不错配、不静默丢图、不假装完整分析 |
| 恢复旧项目 | 布局、参考、参数与结果保持关联，可继续工作 |
| 绘图版块 | 原有排版、提示词服务和生成功能不受 UI 专用改动影响 |

效果验收使用同一组布局、人物或物品，分别提供至少两种明显不同的 UI 风格参考，并实际查看输出。重点判断布局关系、元素身份、风格一致性、层级清晰度及文案可用性；不承诺模型每次都达到像素级位置、精确字形或完全一致的物品数量。

运行源码改动完成后执行 `npm run sync:runtime`、`npm run check:runtime`、`npm run check:entry`，再验证实际页面交互和必要的模型调用。交付时分别报告源码、开发运行文件、启动助手及线上站点的更新状态。本轮仅为方案文档，不触发这些运行检查或发布流程。
