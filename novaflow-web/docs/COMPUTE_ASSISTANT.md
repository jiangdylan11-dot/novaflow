# 对外算力助手

Foart 的用户入口固定为 https://foart.net/ 。对外包运行
`worker/electron/compute-main.cjs`，不提供本地编辑器页面、工程关联或机器授权导入。
首次启动自动登记为待审批设备，默认没有归属账号且所有使用权限关闭。后台命名、分配账号
并开通后自动启动模型环境；以后启动自动连接，无需接入码。节点身份持久保存。
助手只提供官网入口、状态、日志和释放显存；关闭窗口留在托盘，退出停止节点。
界面沿用原助手的 Foart 标题栏、状态/日志页签、硬件和任务卡片和原按钮样式。
对外助手窗口固定为 560 × 480（逻辑像素），禁止缩放、最大化和全屏。日志页填满页签下方可用空间，
长日志只在日志框内部滚动，底部保留打开日志文件夹按钮。
状态页底部预留固定消息区，错误、启动进度和权限说明互斥显示；长错误在区内滚动，
进度说明过长时省略并可悬停查看全文，不会挤压托盘运行提示。
绿色“启动Foart”只打开官网；移除设置页、接入码、手动连接和重复链接。节点名称仅由后台修改，重连不覆盖后台名称。

## 本机开发

`npm run dev` 保留原本地开发助手；`npm --prefix novaflow-web run assistant:start`
保留源码本机测试入口，其既有登录和授权要求不变。
`npm --prefix novaflow-web/worker run dev:compute` 运行新的对外界面。
新助手使用独立的 `Foart Compute` 用户目录，不改旧助手身份、配置及仓库。

## 算力机器设置

后台“算力池 → 机器设置”提供设备归属账号、启用机器、本人使用、对外分享、
共享池或指定账号列表。本人任务按所属账号匹配；这不是网页自动扫描硬件。
普通账号可在官网“我的算力”选择已开通的本人机器，无需开放对外分享。
使用他人节点仍遵循现有账号套餐和节点等级限制；计费规则未变。
后台已移除旧机器码授权页、签发入口及签名密钥状态，不再启动时读取旧授权表。
账号、积分和算力共用的 Supabase 配置保留在“后台连接”抽屉，连接测试读取用户表。
历史授权表、密钥和源码本地测试的授权机制未删除。

`enabled` 与心跳状态独立。停用、关闭分享或撤销账号权限后，不再领取相关新任务；
已经执行的任务继续完成。本人的排队任务优先于他人任务，不抢占已运行的任务。
无账号、无接入码的新 `compute-only` 节点默认待审批，三项权限全关；升级既有节点保留原权限。
登录会话、旧接入码或客户端切换 profile 也不能自行开通新机器；所有新登记路径默认三项权限全关。
后台删除接入码管理界面；在线且尚未分配、所有权限全关的待审批设备可以删除，审批与删除并发时重新校验。

指定账号列表支持用户名搜索、全选和已选人数。无搜索时全选全部账号；有搜索时仅操作匹配账号，
保留其他账号的勾选。清空搜索恢复完整列表，保存包括被搜索隐藏的已选账号。
“全选”只保存当前账号列表，不自动授权以后新建的账号；长期开放仍使用“共享算力池”。

## 部署依赖

1. 依次应用 `supabase/migrations/20261030020000_compute_machine_policy.sql` 和
   `supabase/migrations/20261030030000_compute_auto_enrollment.sql`。
2. 同步并部署更新后的控制面（包含 index.ts 适配器和共享模块）。
3. 按项目正式发布流程更新官网，并发布新后台管理和算力助手。

使用记录保留还需应用 `20261030040000_compute_usage_history.sql`。数据库自动将任务状态、
用户和节点名称、耗时相关时间、模型、扣除积分及失败原因写入独立 `web_compute_usage`；
不复制提示词、参数或生成产物。任务、机器和账号删除不会级联删除此表，后台角色仅可读取，
并阻止该表 DELETE/TRUNCATE。运行进度不变更审计字段时不重复写入。
后台按用户汇总并支持搜索，“查看明细”提供状态筛选、每页 50 条的分页及失败原因。
已存在任务在迁移时补录；此前已经删除的任务不能凭空恢复。已删除节点编号可从现存事件回查，
没有可靠名称时明确显示历史节点编号，不冒用新登记机器的名称。

数据库迁移和控制面必须一起完成才能使用新权限。后台缺少迁移字段时会显示
升级提示而不假报保存成功；助手连接不支持新权限的旧控制面时会拒绝接任务，避免
意外作为公共节点运行。未更新的线上控制面不应作为新助手的功能验收环境。

## 打包及边界

`npm run build:win` 现在输出 `worker/dist-compute/FoartComputeSetup-<version>.exe`。
构建只准备 `compute-renderer` 白名单，不打包完整 `web-dist` 或 `worker-renderer`，
也不含 Spine 编辑器、自动骨架、自动网格等独立模块、本地网页服务和机器授权代码。
后台仍使用 `npm run admin:build`。构建产物和已安装/线上版本分别管理。

本阶段保留节点必需的工作流执行、提示词服务和运行环境。两个历史构建器
`novaflow-brand-runtime.js`、`spine-split-runtime.js` 仍含混合业务闭包，尚未完成核心
提取或加密，不应宣称“完全无核心代码”。实际执行的任务图、参数、输入和结果
在节点上仍可被设备所有者观察。后续加密和核心逻辑迁移另做。

## 验证

`npm --prefix novaflow-web run test:compute` 验证节点启动、无本地编辑服务、包白名单、
绘图/视频工作流图、用户权限和数据库领取策略；它使用本地模拟模型和测试数据库，
不替代真实 GPU 输出验收。`test:compute-ui` 和后台 `test:compute-ui` 用隔离夹具验证
真实 Electron 界面，不接生产账号。原入口仍执行根目录 `check:entry`。

自动登记配额由数据库原子限制：每个可信连接 peer 每小时最多 10 台新设备，全局最多 1000 台待审批。
Supabase 网关可能让多个用户共用 peer 额度；线上真实来源仍需核验，不信任客户端伪造的转发 IP。
