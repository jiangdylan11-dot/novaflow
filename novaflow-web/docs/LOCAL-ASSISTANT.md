# 统一浏览器工作台与本地助手（第一阶段）

## 使用方式

同一份 `web-dist` 同时供线上 WEB 和本地助手使用。本地助手默认提供
`http://127.0.0.1:4784/`，与既有 4783 预览入口分开，避免占用正在运行的测试端。
这不是另一套编辑器源码；本地只注入连接配置，工作流构建仍由 Worker 执行。

1. 打开助手，点击「启动本地服务」。复用已经运行的图像/H3 环境；未启动时调用
   ProgramData 下现有 NovaFlow Runtime 的启动脚本。没有安装的运行环境会报告错误。
2. 点击「打开 NovaFlow」。助手用仅本机可用的随机配对凭证打开浏览器，页面随后移除 URL 中的凭证。
3. 默认选择「本机算力」。本机任务直接进入私有队列，参考文件和结果不走云端。
4. 原 NovaFlow 机器授权从 `%APPDATA%/NovaFlow` 读取，复用机器码、签名验证和在线验证规则。
   可以在助手设置页查看机器码或导入原格式授权。没有有效授权时，服务端拒绝本机生成。
5. 需要提供算力时，登录浏览器里的 NovaFlow 账号，点击「绑定此账号」，再回助手点「算力分享」。
   也兼容设置页原有的一次性注册码。账号节点归属与机器使用授权分别验证。
6. 「停止分享」立即关闭新任务领取，已接任务继续执行，已完成结果仍可通过原凭证下载。
   本机工作台继续可用。「停止本地服务」等当前任务结束后关闭助手接口。

分享每次启动都默认关闭；既有 headless Worker 入口仍按原行为提供共享算力。
助手只关闭自己启动的运行环境，不停止启动前已经存在的客户端运行环境。
本机/共享任务由同一个执行循环串行执行；当前共享任务完成后优先处理本机队列。
切换算力时不迁移进行中的任务，历史结果凭证始终请求原任务所在的服务。

## 开发入口

```powershell
npm --prefix novaflow-web run build:renderer
npm --prefix novaflow-web run assistant:start
```

CLI 会生成本机「打开 NovaFlow.url」快捷方式，使用它完成浏览器配对。
直接输入 URL 可以查看界面，但没有配对凭证无法操作本机队列。
`NOVAFLOW_ASSISTANT_DATA_DIR` 可指定隔离数据目录，`NOVAFLOW_ASSISTANT_PORT`
可指定 CLI 工作台端口；Electron 通过设置页配置端口。

助手运行目录构建：

```powershell
npm --prefix novaflow-web run build:renderer
npm --prefix novaflow-web/worker run build:win:dir
```

正式安装包仍用 `npm --prefix novaflow-web run worker:build`。
产物内含统一 WEB、工作流执行模块和原授权校验模块，不包含模型权重。

## 验证与当前边界

- `local-assistant`：真实 HTTP 私有队列、文件凭证、分享失败不影响本机、停止分享善后、
  本机任务优先、运行中取消、私有与共享文件隔离。ComfyUI 使用明确的测试服务。
- `web-compute-mode`：浏览器适配器不把本机任务回退到云端，不向云端发送配对密钥，
  切换后仍从原服务申请旧任务结果。
- `worker-account-binding`：实际 PGlite 控制面验证账号自绑定、维护状态、不允许换绑、
  重启保留归属；账号会话令牌不保存到节点身份文件。
- `local-assistant-live.test.mjs`：可选真实 ComfyUI GPU 测试。明确使用隔离的测试授权夹具，
  不修改本机原授权、不证明正式账号授权成功。2026-09-22 实际生成并下载保存 512×512 PNG，
  任务 `c32647b8-713c-460c-888a-cc531cb91c51`，结果 236960 字节。
- 实际浏览器已检查算力选择、账号入口、待授权提示和共享登录页返回本机路径。
  从真实绘图按钮提交后，未授权请求被拒绝，界面恢复可操作状态。
- 最终 13 个相关测试套件共 375 项通过、0 项失败；助手运行目录中的本地执行模块、
  网关、浏览器适配文件与源码的 11 项 SHA-256 对比一致，包内模块可正常导入。

本阶段没有退役旧客户端，也没有声称所有桌面专属功能已经等价迁移。
H3 视频、新电脑自动安装运行环境、原生文件操作/编码能力的全量等价验收仍需继续。
线上站点和生产控制面未在本次部署；现有本机 4783 服务未被替换。

当前电脑默认 `%APPDATA%/NovaFlow` 目录中的授权返回 `locked / license_rejected`。生产授权路径会拒绝本机生成，
不能把测试授权夹具的出图成功当作正式账号可用。

根目录 `sync:runtime` 因这个 WEB 工作区缺少桌面 `@jsquash/webp` 依赖而失败；
`check:runtime`、`check:entry` 因桌面 renderer/dist 文件缺失未通过。
现有 4783 和 8188 健康检查成功，不等于新助手通过桌面入口验收。
助手目录构建成功；启动新构建的 EXE 做原生窗口验收被自动审批拦截，
返回仅为 `blocked by policy`，没有更具体原因，因此该项未验证。
