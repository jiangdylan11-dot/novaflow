# Web 本地仓库映射

## 原因与修改

正式网页的仓库快捷入口调用 `runtimeOpenOutputFolder`，但 Web runtime 与 capabilities 都只返回“不支持本地目录”；入口未呈现该错误，造成点击无反应。

新增浏览器专用 `novaflow-web-warehouse.js`，并通过现有快捷入口打开仓库面板。该模块只进入网页，不进入算力节点。无需更新 Worker 或云端函数。

- 首次在“仓库 → 连接 / 更换文件夹”选择本机目录并授予读写权限。
- 生成输出下载成功后，图片和视频进入同一个本地保存队列；参考图、输入遮罩不在此入口入库。
- 未连接目录或权限失效时，结果暂存于当前浏览器的 IndexedDB，面板显示待保存数量；恢复授权后重试。若浏览器暂存失败会提示保持页面打开。
- 文件夹映射保存在同一网站、同一浏览器配置下；权限恢复由用户主动点击触发，后台不会反复弹授权窗口。
- 文件名附加内容哈希，重复取回不会反复写入；遇到现有同名但内容不同的文件会改名，不覆盖用户文件。
- 面板显示所选文件夹根目录的前 200 个媒体文件，可预览图片和视频。断开映射不会删除磁盘文件。
- 本地文件只在浏览器中读取预览，不因映射而上传到控制面或算力节点。

建议选择固定的作品文件夹。桌面旧入口对应按会话管理的 `ai-sequence-cache` 临时目录，映射到该临时目录并不能改变桌面的清理策略；本次没有修改原桌面项目。更新前网页内存中的历史结果不会自动迁移，新版本接收的生成结果开始自动入库。

## 验证与发布状态

- 仓库存储测试 18 项通过：实际临时磁盘写入、原始字节一致、待保存结果跨初始化恢复、权限丢失与恢复、重复结果去重、同名文件保护、取消选择保留旧映射、断开不删文件。
- 网页构建 78 项、生成路由 38 项通过，总计 134 项通过。
- 浏览器独立组件页已实际点击打开面板，确认映射、刷新及关闭入口可见。
- 按项目约定尝试三个桌面同步/检查命令。Web 工作区缺少桌面 `@jsquash/webp`、renderer/dist，检查未通过；本次仅改动 Web 运行文件。同步造成的无关换行变化已恢复。
- 更新 ZIP 已构建，控制面仍指向线上 Supabase；未包含独立组件验收页。
- 自动选取上传 ZIP 被 Chrome 扩展文件访问权限拒绝，已停在 Cloudflare 上传页，等待用户手动选入 ZIP 或启用扩展的文件 URL 权限。尚未发布，尚未完成正式网页目录授权与真实生成自动入库验收。

安装包：`novaflow-web/.artifacts/novaflow-web-warehouse.zip`。

目录授权参考：[Chrome File System Access API](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、[showDirectoryPicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)。
