# Worker 0.4.2 启动重试修复

2026-09-22，安装后的 0.4.1 显示离线，图像和视频运行服务均健康。日志显示自动注册返回 `missing session token`；用已保存的节点身份调用云端登录得到 `unknown worker`，说明该身份的云端节点记录已经不存在。未确认记录消失的原因。

用户随后保存了注册码，但再次点击启动没有重试：Electron 保留了失败的 Worker 实例，直接返回它的离线状态；核心层也保留了启动标志、网关与隧道。

## 修复

- 启动失败后释放端口、隧道、定时器与临时令牌，恢复可重试状态。
- Electron 清除失败实例，下次启动重新读取已保存的配置。
- 合并同时发生的启动请求，防止重复占用端口或消耗注册码。
- 注册身份不存在、注册码不可用时显示对应的中文提示。
- 安装包版本升级到 0.4.2。

## 验证

- `worker-onboarding` 51 项通过，`worker-start-retry` 16 项通过。
- 新测试通过真实 HTTP 注册失败、同一端口重新绑定证明资源释放；通过实际 Electron 主进程入口注册的 IPC 验证“失败、保存新码、重新启动”及并发启动。
- 本机用用户已经保存的注册码重新注册成功，Qwen 与 H3 模型上报 Ready；云端显示两个算力池均有 1 台节点。
- 0.4.2 已打包，解压核对主进程、Worker 核心与源码相同；安装到原目录后再次核对一致，保留原身份与设置。
- 按仓库约定尝试了 `sync:runtime`、`check:runtime`、`check:entry`。Web 工作区缺少桌面 `@jsquash/webp` 依赖和桌面 renderer/dist，桌面检查未通过；这些不是本次 Worker 注册重试测试。同步产生的无关换行变化已恢复，原本地端目录未修改。

安装包：`novaflow-web/worker/dist/NovaFlowWorkerSetup.exe`。此次不更新网页或云端函数。
