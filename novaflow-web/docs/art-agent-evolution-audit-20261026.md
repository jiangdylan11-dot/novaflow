# 美工 Agent 持续进化：现状审计与第一、二阶段

审计日期：2026-10-26。范围为美工，保留当前生成与 Flash 资源交接，云端经验服务仅准备源码和本地验收，尚未部署或写入 Supabase。本文以当前会话的最新决定为准：不建立个人长期经验库；只有项目所有者可以发布共享知识。

## 1. 当前 Agent 能力

实际入口为 `renderer/xiaotao-art-agent.js` → `renderer/novaflow-web-runtime.js:artAgentChat` → 本地已配对的 `worker/src/local-server.mjs` → `strata-prompt-assistant.mjs` → `flash-art-agent.mjs`。

- 本地普通文字/图片对话、双图画风迁移、新建绘图及当前成图修改。
- 原生工具：`get_art_context`、`propose_art_direction`、`apply_art_direction`、`generate_art_image`。前三者不生成图片；最后一个仅产生应用执行提案。
- 当前快照指纹、重复请求拦截、对话忙锁、三轮上限；双图任务默认可以直接调用最终工具，毋须额外读取快照。
- 用户确认采样，应用校验参考图及参数，Flash 释放确认后才允许通过既有绘图管线生成一张。没有自动审图重试。
- API 大脑目前只有 Grok 文字聊天（`companionCloudChat`），没有图片和应用执行权限。GPT 尚无此 Agent 入口，不能把统一知识接口等同于已经完成大脑切换。

- `local-tasks.mjs` 复用本地 dataDir 原子 JSON 文件存储执行任务；现有 Supabase 登录/额度保持原用途。
- 未发现已接入 Agent 的私有经验检索、精确结果反馈、公共发布审批或技能回退闭环。

## 5. 已落实的职责划分

- `art-skills/style-transfer.v1.json`：原完整专业正文独立成技能 1.0.1，正文 SHA256 不变。特定 Flash 大脑的推理策略与通用美术规则分开。
- `art-learning.mjs`：本地任务日志，含请求、参考素材 SHA256、实际 prompt/参数、工具、成图编号及 SHA256、修改父任务、明确反馈；按已绑定账号或已配对设备隔离。原始图片像素不进入该日志。不建立个人长期经验库。
- `art-knowledge-cache.mjs`：启动/定时后台增量检查版本；生成只读本地缓存，不等待云端；离线、非法包、部分写入或同版本篡改均保留最后有效版本。历史版本不可覆盖，支持服务端回退后的指针切换。
- `flash-art-agent.mjs`：有界共享方法仅作为 user 消息中的任务数据，不能修改 system 权限；最多取适用的 5 条。正式经验为空时使用原专业技能。可在原生工具结果中附带一条抽象 `learningMethod`，没有额外总结模型调用。
- 自然语言反馈绑定当前选中的真实成图及实际任务；沉默、重生成和技术成功都不视为满意。只有产生了不同 prompt、不同结果且明确满意的修改链才标记“改进信号”，该信号仍不等于验证结论。
- 去重合并方法及证据。原始图片、完整任务 prompt、私有聊天不发送到共享候选 API；只接受有界抽象方法、适用范围、结果摘要、评价类型及暂定改进信号。敏感内容过滤只是第一道检查，最终仍需所有者审核。
- UI 移除“个人经验”、应用经验复选框、满意/不满意专用按钮和保存经验按钮。反馈不显示“已入库”提示。普通生图仍走原执行流程。

服务端接口、SQL 和本地完整验证已经准备；所有云端读写默认关闭。普通用户只能提交已授权候选、读取正式版本；客户端没有正式表写权限。缓存和上传均不加载 Flash；云端失败不会追加生图、审图或重试任务。

## 6. 只有所有者可以发布

当前会话最新要求覆盖原任务书中的“管理员发布”：不是所有管理员都能发布。`art_knowledge_policy.publisher_user_id` 必须由部署者明确绑定用户本人的账号 UUID；空值一律拒绝，不能由首次调用者抢占。用户账号还必须处于 active 且具有后台管理员角色。普通管理员可以查看抽象候选，不能 prepare/publish/rollback。

流程：正常创作与明确反馈 → 在已授权情况下后台提交候选 → 服务端去重/合并证据 → 发布准备阶段自动生成待审清单 → 本人明确批准这一批 → 服务端发布不可变版本 → 客户端后台同步。

`POST /api/web/art-knowledge/prepare` 不发布：过滤已发布重复项、无正面证据的候选；保留反面证据和仅单用户证据提示。即使有很多满意，也必须附上通过的固定基准记录。最多选 20 条，正式知识包最多 100 条，不无限拼接历史 prompt。

待审摘要绑定：目标技能/版本、当前正式版本、候选方法完整文本及适用范围、最新证据摘要、完整固定基准验证信息、可选技能包。本人发布请求必须携带相同摘要及显式同意。方法、证据、基准或正式基础版本有变化必须重新准备。SQL 在同一事务中再次核对证据，避免检查与发布之间的竞态。后续新增候选不会混进已批准批次。

新版本保留原有正式方法；不会因只批准两条新增经验而清空旧库。回退只能切换到已存在的历史正式版本，并且也只有本人能操作。服务端密钥只在服务端持有，表/RPC 对 anon/authenticated 无直接访问授权，全部启用 RLS。

### 发布准备命令（尚未连接云端执行）

在每次计划发布前运行只读准备步骤，将报告展示给本人。经验数据发布与软件部署分开：经验更新以后无需重新打包或部署客户端。未批准的候选继续保留，不影响原正式版本。

```powershell
# NOVAFLOW_ART_OWNER_TOKEN 仅保存在本机环境，不进入 Git 或报告。
node novaflow-web/tools/art-knowledge-release.mjs --prepare --control https://正式控制面 --version 1.0.2 --benchmark 固定基准结果.json --report 待审经验.json
# 自动产生 JSON 和中文 Markdown 报告；先读报告，再由本人明确同意：
node novaflow-web/tools/art-knowledge-release.mjs --publish --control https://正式控制面 --report 待审经验.json --approve-batch 报告中的完整摘要
```

基准文件格式为 `{ "passed": true, "cases": [真实验收案例...] }`。程序计算整个基准文件的 SHA256，不以“生成成功”代替美术验收。目前为独立的发布准备工具，尚未强行接管网站原有部署命令；正式接入部署流程、后台可视审核页及发布人 UUID 配置都应在上线前完成。没有本人明确同意，不能运行 publish、数据库迁移或部署。

## 7. Supabase 与授权、缓存、成本

| 数据 | 位置 | 边界 |
| --- | --- | --- |
| 当前任务连续修改上下文 | 本地/执行端日志 | 按账号隔离，最多 200 个任务；不是个人偏好库 |
| 原始素材 | 既有资源系统 | 不复制到共享经验库 |
| 抽象候选与反馈证据 | Supabase（源码待上线） | 用户明确授权后才提交，不包含原始反馈全文；不直接生效 |
| 正式方法、技能包与版本、批准摘要 | Supabase（源码待上线） | 只有本人发布，不可覆盖历史内容 |
| 已批准知识缓存 | 本地 dataDir | 启动后台同步、每 60 秒检查；正常生成不发数据库请求 |

用户是否安装本地助手与是否有发布权无关。本地助手只提供本机执行与缓存；共享候选身份来自服务端验证的登录账号；服务端仍校验贡献授权，默认未授权。原有 API 大脑尚无图片/执行适配器，不宣称已完成 GPT/Grok 绘图切换。

上线开关默认 false。启用后，浏览器以当前登录账号查询授权、后台发送 method-only outbox、成功后精确确认已上传证据；断网保留队列、稍后重试；切换账号时不继续上传上一账号的数据。用户无需每次选择经验类型。账号层面的共享授权入口仍需与正式隐私设置衔接，不能以“用户无感”为理由默认同意。

可选迁移文件 `supabase/optional-migrations/20261026010000_art_knowledge.sql` 当前只在临时 PostgreSQL 测试库执行。该文件存放在正式 migrations 目录之外，不会随常规 db push 自动生效；只有本人明确批准后才移入正式迁移流程。

容量按有界知识包、去重证据和限流控制。正式方法每包 <=100、候选每次 <=20、单用户每小时最多 100 条新证据，客户端包 <=128KiB，任务只命中 <=5 条。当前审核读取最近 500 个候选；大量用户开放前仍需补齐分页、候选保留期限、监控及定期压缩策略，不以本地测试代替容量验收。未查询当前 Supabase 套餐和实际用量，不能承诺零成本。
