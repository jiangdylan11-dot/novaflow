# 中文提示词输出与手动编辑

本人明确要求软件中生成的提示词也能使用中文编辑。本轮处理语言和编辑交接，不恢复已否决的候选画风默认值，不改美术规则正文、生成采样、GPU 调度或共享经验架构。

## 实现

- 小桃本地/在线请求以及普通完整双图分析请求带 `promptLanguage: zh-CN`。本地调用在原有系统规则之后追加请求级语言合约，并为工具的提示词字段提供中文输出说明；没有独立翻译调用或双语重复正文。省略语言设置的旧客户端保持原有行为，明确英文请求仍可使用原线路。
- 本地绘图/创作返回的提示词可直接写入已有可编辑提示框。参考图标记、指定画进图中的文字（例如 `OPEN`）、专名、负向词和手动参数保留各自职责。
- 在线图片分析与文字网关默认提供中文绘图提示词，仍保留原有授权、额度计数及无执行工具边界。没有新增云端生图权限。
- 用户手动修改正向或负向输入时，清除此前待执行的 Agent 方案，避免普通生成按钮先消费旧方案。既有直接绘图路径按编辑后的正文映射参考图编号，没有新分析或英文重写。
- 历史英文提示词、原图和已封存基线不自动改写。中文/英文转换可能改变实际文本；本轮不以语言修改证明画质相同。

内置美术技能仍为 1.0.11，正文 SHA-256 为 `9ee27938e8cba9864728f84540e22deb5ad7c1727677cb92396ef3a00e846c28`。请求级语言设置使用单独的实际系统摘要记录，不冒充旧英文请求的系统摘要。

## 验证

真实本地调用一次，只返回提示词，没有生图或额外翻译。返回 369 字符中文正文、完整双图编号和中文内容摘要，工具为 `propose_art_direction`；分析后资源已释放，机器全局配置未修改。

该单例仅验证实际中文输出，不证明画质等价或整体速度改善。

124 项专项检查通过，包括：旧默认规则保持、普通客户端兼容、请求级中文合约、单次模型交接、中文原样写回、手动编辑后直接编译、参考图编号、实际负向内容、CFG 3 和无自动生成。`sync:runtime`、`check:runtime`、`check:entry`（4 个文件、286 项内部断言）通过。

扩大检查还遇到既有问题：`art-direction.test.mjs` 的两个旧 Qwen 节点结构预期和一个 PE 错误文案预期失败；`ui-design-surface-lifecycle.test.mjs` 缺少 `isXiaotaoArtRuntimeElement` 测试依赖。使用修改前的 HEAD 文件进行只读替换验证，分别复现相同的 3 项和 1 项失败，未为本任务修改这些无关行为。专项通过不表示全量回归无失败。

## 使用和生效范围

新提示词可在原提示框中直接修改中文。真实示例：

> 以@参考图2为画风参考、以@参考图1为内容原图，按图2的精致半写实动漫绘画语言重绘图1……

完整示例在 `D:/AI_APP/NovaFlow-Web/work/chinese-prompts-20261026/prompt.zh-CN.txt`；该文件只将实际模型输出中的 `<imageN>` 按现有界面规则显示为 `@参考图N`，不修改美术正文。

源码与开发运行文件已更新。本轮没有打包、部署、替换已安装助手、发布 Supabase 经验或生成新图。现有线上/安装版需要对应更新后才会默认发送中文语言设置。
