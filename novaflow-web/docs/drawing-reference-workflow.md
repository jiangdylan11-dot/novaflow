# 绘图参考驱动流程：实现与验证记录

日期：2026-10-23。范围为美工的“绘图”页，UI 设计流程保留原入口。

## 使用方式

- 添加参考图，写一句用途关系，例如“图1用图2画风”，直接生成。
- 也可选择“转二次元”等任务后直接生成，提示词允许留空。
- 每张参考的用途默认为自动，必要时可指定主体、风格、姿势、背景、材质、配色、构图、光影或物件。
- 本地分析 / Grok 分析是直接线路选择。原提示词保留；分析结果可查看，不增加优化提示词的二次确认步骤。

## 实际处理链

`runArtGenerate → NovaFlowArtDirection.prepare → 实际视觉分析 → 用途校验 → 参考隔离 → 已有生成路由 → 实际成图检查`。

主体保留像素；风格和材质提取局部样本；姿势使用真实 MediaPipe 关节点；背景使用已捆绑的 BiRefNet 隔离检测到的无关前景；配色使用主色统计；构图和光影分别转换为粗几何和低频明暗。禁止用未处理的风格图或姿势人物原图作为识别失败的静默回退。

用户明确的用途是白名单，否定用途是黑名单。辅助图的自由描述不直接成为成图要求；风格、材质和环境只允许有限的相应用途语义进入指令，避免把能量、道具和参考人物引入。姿势图会被单独观察一次，再筛选仅含人体几何的动作描述，转换为明确的正向编辑指令。应用目标必须来自用户原文；主体原有配饰另有保留约束。

图像通过独立输入上传，不复制到任务控制 JSON。参考图、用途、提示词、任务、尺寸或线路在分析期间变化时，旧结果不能提交。取消会丢弃迟到的分析结果。已经开始的后台生成允许用户切换页面。

成图检查比较输出和原始参考。姿势另有独立的实际关节点方向对照，不以语言模型的“通过”结论覆盖明显肢体偏差；少于六个可靠肢体段的局部检测不能成为额外人物。偏差时本地生成最多自动纠正一次；云端不会静默追加第二次付费生成。检查失败或未完成会明确保留状态，不能视为效果验收通过。Grok 分析及成图检查使用现有 Grok 次数。

## 真实样例与证据

验证使用现有 RTX 4090 Laptop / Qwen-Image-2.1，本地 GPU 作业逐个执行。前端提取在真实 Chrome 中执行，生成经过本地助手的真实任务接口和注册工作流构建器，输出直接来自 ComfyUI。组件验证页不能替代绘图主页面验收。

私人验证产物保存在 `work/art-direction-20261023/`，不进入发布包：

| 样例 | 实际结果 |
| --- | --- |

| 真人女照，“水彩画” | 明确转为水彩晕染和纸面肌理；已目视核对 |

初版四路结果确实发生过骨架线条泄漏、背景未替换，失败文件已保留。增加单图姿势观察、受限正向动作/材质/环境描述及独立姿势核对后，上述组合取得明显有效结果。实际失败样例的肢体方向差异为 1.247，修正样例为 0.099（通过阈值 0.42）；这是肢体方向度量，不覆盖人脸朝向、手指细节或所有画面质量。曾出现本地语言模型把骨架泄漏图误判通过，因此不能把模型检查结论当成用户效果验收。

## 代码与验证边界

核心实现位于 `renderer/art-direction.workflow.js`，隔离组件在 `art-reference-safety*` 与 `art-reference-foreground.js`，独立姿势度量在 `art-pose-validation.js`。本地分析在 `particle-editor-desktop/prompt_assistant/art_direction.py`；Grok 请求与结果协议在 `admin/admin-server/art-direction.js`。

34 项绘图及姿势 JavaScript 测试、7 项 Python 测试通过；连同参考容量、原 AI 助手、UI 邻接入口、独立像素上传与共享 Qwen 路由的针对性回归，共 65 个 Node 测试入口通过（共享 Qwen 文件另报告 26 个断言）。`sync:runtime`、`check:runtime`、`check:entry` 通过。检查与构建成功不代表所有角色的成图质量已经通过。

源码和开发运行副本已同步；未打包、未安装、未部署、未推送。开发主页面仍需登录后才能完成用户实际入口的端到端验证。实际组件链路已验证照片转风格和四路组合的主要作用，但严格姿态细节、更多任意参考和云端高质量生成仍未完成全面验证；当前不能宣布整个优化目标完成。
