# 绘图参考驱动流程：实现与验证记录

日期：2026-10-23。范围为美工的“绘图”页，UI 设计流程保留原入口。

## 使用方式

- 添加参考图，写一句用途关系，例如“图1用图2画风”，直接生成。
- 单张参考图可写“二次元”等简短效果词；参考用途明确时也允许提示词留空直接生成。任务下拉框已移除，界面不再要求重复选择任务。
- 每张参考仅显示原始图号，没有用途下拉框。由“图1人物、图2画风、图3姿势”等短句自动理解职责；主体、风格、姿势、背景、材质、配色、构图、光影或物件的内部职责仍保持独立。
- 本地分析 / Grok 分析紧跟正向提示词标题行的“历史记录”，不占用输入正文；绘图页移除旧 AI 助手入口和重复“需求分析”文字。“查看分析”放在生成状态旁，窄区域的正反提示词会换行排列，避免标题栏拥挤。原提示词保留；分析结果可查看，不增加优化提示词的二次确认步骤。

## 实际处理链

`runArtGenerate → NovaFlowArtDirection.prepare → 实际视觉分析 → 用途校验 → 参考隔离 → 已有生成路由 → 实际成图检查`。

主体保留完整原图像素，不接受分析模型擅自裁剪；风格使用完整原图以保留五官关系、材质细节和整体照明，材质仍只提取指定表面；姿势使用真实 MediaPipe 关节点；背景使用已捆绑的 BiRefNet 隔离检测到的无关前景；配色使用主色统计；构图和光影分别转换为粗几何和低频明暗。风格图完整输入是明确的职责条件；姿势仍使用骨架，禁止在识别失败时静默回退为姿势人物原图。

画风定义包括绘画语言、眼鼻口比例和概括方式、面部体积及主光方向、软硬、冷暖、对比与轮廓光。单独观察完整风格图的媒介、五官、线条、上色、质感、照明和配色七项实际画法，不再用有限风格关键词代替原画法。主体辨识特征、主要动作、服饰类别、持有物与场景类型取自主体图；人物比例、轮廓、衣褶、背景安排和细节允许重构，成图质量、目标配色和协调氛围优先；五官比例、轮廓概括、头发组织及整个画面的渲染与照明按风格图重绘。允许改变摄影轮廓和写实五官比例，不代表可以更换人物、服装、动作或背景内容。明确的“保持原构图”等要求，或单独的姿势/构图参考，约束相应维度。换风格不继承 UI 精修的空间锁定；主体完整原图仍参与参考条件，不能把空 latent 等同于已消除照片画法偏置。

用户明确的用途是白名单，否定用途是黑名单。辅助图的自由描述不直接成为成图要求；风格使用完整像素并明确禁止借用人物、服饰、姿势、背景和物件，材质和环境只允许有限的相应用途语义进入指令，避免把能量、道具和参考人物引入。姿势图会被单独观察一次，再筛选仅含人体几何的动作描述，转换为明确的正向编辑指令。应用目标必须来自用户原文；主体原有配饰另有保留约束。

图像通过独立输入上传，不复制到任务控制 JSON。参考图、用途、提示词、任务、尺寸或线路在分析期间变化时，旧结果不能提交。取消会丢弃迟到的分析结果。已经开始的后台生成允许用户切换页面。

成图检查比较输出和原始参考。姿势另有独立的实际关节点方向对照，不以语言模型的“通过”结论覆盖明显肢体偏差；少于六个可靠肢体段的局部检测不能成为额外人物。偏差时本地生成最多自动纠正一次；云端不会静默追加第二次付费生成。检查失败或未完成会明确保留状态，不能视为效果验收通过。Grok 分析及成图检查使用现有 Grok 次数。

## 新下载的 BF16 与 PE-I2I 对照

本机新增的 `qwen-image-2.1-UC-BF16.gguf` 为 297 个 BF16 张量、约 13.25 GiB，与现有 UC-Q8_0 架构和参数量一致。直接使用 GGUF 量化层加载器的任务 9887994f-7405-4ef0-8ea8-a22f769694c4 出现严重低速，约十分钟只推进少量采样步，已核对队列后仅中止该诊断任务，未停止用户的 Comfy 服务。读取本机加载器发现 BF16 也进入逐层还原 FP32 再转换计算类型的路径；这是疑点，不以源码推断替代性能实测结论。

从用户已下载文件生成原生 `qwen-image-2.1-UC-BF16-native.safetensors` 副本。297 个张量的 dtype、shape 及每个张量原始 BF16 字节 SHA256 全部核对一致，没有更改数值、追加量化或重新下载权重。原 GGUF 保留。原生 UNETLoader 的 2 步短测试任务 53fcfc71-5bfa-44c1-9cec-7ef5c824b596 约 27.2 秒完成（第一步在 16.7 秒，第二步在 23.1 秒），显著快于异常 GGUF 路径；2 步图只用于性能排查，不作为画质证据。

用户随后新增 `qwen3vl_8b_bf16_heretic.safetensors` 编码器，约 16.33 GiB、750 个 BF16 张量；当前 W4A8 编码器约 5.88 GiB。对应嵌入形状均为 151936×4096。编码器和生图模型应分阶段在内存/显存之间调度，不能以两套权重相加超过 16GB 宣称不可用，也没有将 CLIPLoader 强设为全程 CPU 推理。

另核对现有 UI 的 `qwen3.5_9b_qwen_image_2.1_pe_i2i.int8_convrot.safetensors` 是真实 CLIPLoader + TextGenerate 推理，不是仅模型名称标记。官方明确 PE-I2I 是专门训练的多参考图编辑指令增强模型，必须使用相应系统提示与 thinking；它与图像生成用的 Qwen3-VL 编码器职责不同。只读核对现有 UI 线路，未修改 UI 专用规划实现。

以完整两张原图（分析用等比例补白到相同尺寸，禁止 ImageBatch 中心裁剪）和“图1用图2画风”，官方 PE-I2I 任务 7c09c256-cede-4a3d-abf2-9286d5f5c3fb 约 107 秒完成。能描述干净轮廓、平涂结合软渐变、明亮配色和整体重绘；同时过度锁定原布局，猜错背景牌文字，并从闭眼风格图推断了未见的睁眼比例。其原始指令经 Q8、CFG1 任务 6fc50ea5-f3dc-42f1-a8f2-b6a96b0080fe 实际出图，约 87.6 秒，仍偏暖与插画，不能把 PE 名称或结构兼容性当作风格验收通过。这是绘图主入口集成之前的诊断记录。

## PE 与通用 Qwen3.5-9B 的选择

本机 `qwen3.5_9b_bf16.safetensors` 约 17.98 GiB，775 个 BF16/F32 张量；PE-I2I INT8 ConvRot 文件约 8.82 GiB。前者的权重结构符合通用 Qwen3.5-9B，仅凭文件名/张量结构不能证明全部原始权重来源。PE 是专用编辑指令微调，两者的训练任务差别不能用文件大小或量化精度代替。
