# H3 多参音频导入 2.0.91

入口：动画视频生成 → 本地 beta5 / 本地 beta6 → 多参视频 → 添加参考音频。仅改本地多参；图生、首尾、图片展示与横向布局未改，未新增批量入口。

单个有声视频拖入或选择到音频参考时，复用现有 `electronAPI.extractAudioTrack` 和已打包 FFmpeg WebAssembly，探测音轨并生成真实 44.1kHz / 双声道 / 16-bit PCM WAV。保存为 kind=audio 的独立参考，显示“参考音频 N”；视频原文件不改，该次导入不添加视频帧。中间文件使用原媒体工具的受管虚拟临时文件系统，结果进入现有 H3 IndexedDB 素材库；临时文件及复制后的输出缓存清理。

无声、损坏、时长不符或满额文件不创建卡片，通过项目现有 window.alert 弹框提示；关闭后回到触发入口，入口消失时回到可见的同类素材。移除原底部错误 span/CSS，不添加行、不挤压版面。保留最多 3 音频、单个 2–15 秒、合计最多 15 秒。

导入串行执行、重复的进行中来源去重。异步结果固定写回启动时的 boardId，后台写入不激活旧板块；提交快照等待当前板块导入完成。失败不破坏已有素材，失败后可重试。原选择方式保持；用户已明确以一次一个文件为验收范围。

之前“正常 WAV 未入库”只出现在构造的混合批量测试：开头的失败视频先占用了名额，后面的正常 WAV 被提前判满。单文件 WAV 不存在该回归；已补充独立实际界面验证。没有将该夹具场景当成实际 UI 必需功能继续扩展。

## 验证

源码和最终包中，两条模型均以真实 FFmpeg WASM 验证，非媒体引擎 mock：

- 单个 3 秒有声 MP4 生成 534,454 字节 PCM WAV，实测 3.029342 秒，RIFF/WAVE 头正确。beta5 用拖放，beta6 用文件选择；原视频字节哈希保持。
- 单个无声视频、单个损坏视频各出现一次明确错误弹框；已有素材数量不变；关闭后焦点回到音频入口。
- 单个正常 WAV 独立导入成功、无错误弹框；错误前后整个生成区和提示词矩形完全相同，无底部错误元素。
- 进行中的实际提取加测试延迟后，重复拖放只调用一次真实提取。删除已有参考、切换模式/模型、等待提交快照、容量满额及 IndexedDB 重开保持正确 sourceId。
- 提取结果与单独正常 WAV 经真实本地队列保存、文件重映射和包内 workflow host 构图，两份 Audio 输入都绑定到 MiniMaxH3ReferenceToVideo，Video 输入与 LoadVideo 节点为 0。
- 6 组 CPU 导入防护检查及既有 H3、提示词、媒体工具合并 10/10 通过；原媒体工具内部 113 项通过。源码及包内原界面 34 场景 + 11 时序/返回/恢复检查通过，@ 与三类卡片行为保持。
- sync:runtime、check:runtime、check:entry 通过；entry 四文件内部检查为 48 / 63 / 138 / 32。首次同步曾在生成文件暂时缺失时失败，串行重新同步后全部文件语法及一致性检查通过，未操作其他进程。

本轮没有下载依赖或模型，没有 GPU / 付费调用，没有自动安装、重启、前台接管或网站/Supabase 部署。其他窗口工作保留。
