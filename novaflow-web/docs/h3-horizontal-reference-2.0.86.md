# H3 横向参考栏与素材类型修复候选 2.0.86

本次针对用户在 2.0.85 实际界面反馈的窄栏、纵向滚动、素材仍有加号和类型不可辨识问题。未读取用户新截图像素，依据主会话已查看的像素反馈和明确文字规格实施；未重试失败的 Library 下载流程。

## 根因及修复

- 旧运行时为参考列反复写入固定宽高，2.0.85 又按三个旧槽位计算列宽；素材列表的 wrap + overflow:auto 导致右侧空间闲置、素材纵向堆叠。
- 原 nfAiSeqRefDropzone 以“有图片 dataUrl 或 mediaName”判断是否占用，并在没有图片时直接画加号。视频/音频未作为预览类型处理。
- 实际上传样式归一化会把卡片内部 div/span 强制 position:static，导致新增类型/时长覆盖层挤到预览旁边。

保留原参考列 DOM 挂载点，在同一个生成区中使 H3 参考栏占满可用宽度，仍在参数/生成进度之后。仅 H3 使用满宽参考栏的布局规则；退出 H3 多参模式时恢复旧属性。卡片保持原 132px 外框，在一条连续横行中排列，超过宽度横向滚动，overflow-y:hidden，不再以旧槽位宽度限制素材栏。已上传素材全部在前，尚可添加的图片/视频/音频入口在末尾，独立满额隐藏，删除后恢复。

原外框组件继续复用；已上传卡片使用明确的媒体预览分支。图片显示缩略图与“图片”，视频显示预览/播放图标、“视频”和时长，音频显示音符、“音频”和时长。文件名保留为悬停信息，不代替类型。加号只在添加入口；占用卡片的原加号节点和 ::before/::after 伪元素均被排除。预览内容也计入原组件占用条件，保证视频/音频有删除按钮。旧样式归一化只跳过 H3 预览内部节点，其他组件不变。

9 图 / 3 视频 / 3 独立音频的模型线路、存档结构、sourceId、提示词绑定及最终节点连线没有改变。
