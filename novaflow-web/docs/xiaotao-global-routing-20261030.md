# 小桃全局路由、上传等待与算力池修复

## 用户交互

小桃根据用户要制作的结果选择绘图、视频或音频，不要求用户选择内部素材槽位。普通图片分析留在对话中，明确的背景修改自动准备图生图输入；单张图片的循环动画自动使用同图首尾帧。当前打开的版块不再强制决定小桃的任务，对话跨版块保留。

用户意图不确定时，模型可询问一个关于目标、效果或素材身份的具体问题。提问不产生执行提案；用户回答后保留原任务时长和要求继续，而不是把补充说明当成另一项任务。绘图和音视分别使用 `ask_art_question`、`ask_media_question`；不会让用户判断内部槽位名称。

## 实际问题与改动

- 旧上传路由只识别明确的版块名字，未命中即弹出五种素材位置。新路由按需求自动准备，未指定用途的分析图片作为对话附件。
- 视频引用错误地经“动画”入口同步查找输入框，既没有进入音视视频入口，也没有等待 React 渲染。现在通过原音视入口切换，等待实际模式、原生输入框和图片导入完成；生成参考不再重复上传进通用资源列表。
- Qwen 原生参考图会异步填充尺寸。实际复现了快照先记录 1024×1024，随后原生加载将其改成 480×864，小桃误判为用户改动并主动停止。现在等待尺寸填充完成再记录快照，保留原有素材和参数变化防护。
- 图片预览使用浏览器异步 FileReader，避免逐字节构造大字符串。上传准备期间禁止重入，失败保留文件，不继续提交空任务。
- “做一个2秒的循环动画”未命中旧执行动词规则，被前后端当作纯对话。现在两端都识别这种明确制作请求，仍保留讨论、否定和提示词请求的非执行规则。
- 视频规划快照补充当前参考位置、首尾标签、真实来源 ID 和占用状态，避免模型把已上传图片误说成未提供。
- 音视分析与执行使用自己的完整快照检查，不再被旧绘图提案或采样确认状态误停。
- 网站小桃曾在请求算力池前，按页面是不是由本机助手启动直接拒绝。现在通过既有 `prompt_assistant` 任务传输 `art-agent-chat`，遵循当前选中的节点，未固定节点时保留会话节点亲和性。停止只取消自己的请求；节点在输出结果前独立确认模型释放，不读取远端请求者的本机账号学习记录。
- 页面缺少本机助手不再等同于没有算力。节点确实未报告小桃能力时，才提示检查当前节点的模型服务。算力节点需要运行包含新任务操作的新版助手。

## 效果和验证边界

- 红球视频是 480×864、24 FPS、56 帧，约 2.33 秒。原模型帧对齐策略未改，不能声称精确 2.00 秒。
- 红球起跳并回到接近起点，首尾中心约为 (132.99,475.83) 与 (140.51,478.09)；运动中仍有水平漂移，不能声称完美原地运动或逐像素无缝循环。
- 真实页面响应计时持续运行：背景修改的最大计时间隔约 0.51 秒，循环动画约 1.13 秒；未出现浏览器整页无响应。原用户浏览器完整卡死现场没有单独复现，因此不能据此宣称所有项目和浏览器下的卡死均已排除。
- 真实生成使用红球测试素材；用户截图里的角色原图没有作为独立文件提供，不把测试素材结果冒充该角色的效果验收。
- 已验证的发布状态应以本次发布记录为准；源码验证不能代替安装新版算力节点助手或线上登录后验收。
