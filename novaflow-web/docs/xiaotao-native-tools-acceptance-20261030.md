# 小桃原生工具接入与验收（2.0.178）

小桃负责沟通、观察、规划、提示词优化和调用 Foart 工具。它自身不生成图像、视频或音频。普通生图仅沿用对应本地模型或 GPT Image 2.5；视频沿用原有本地 H3 工作流，不新增在线生视频。

## 接入范围

- 美工：绘图和 UI 工作区、生图与原有模型优化入口、图层和参数控件、画布调整、拆图、抠图、钢笔选区、蒙版、修复、高清放大、扩图、角度调整、万物迁移、姿势参考、原生导出。
- 视频：文生、图生、首尾帧、多参各自的原有提示词协议与引用；资源选择与上传、时间轴编辑、画面变换、蒙版、抠图、调色、帧编辑和原生保存/导出入口。
- 音频：原生音乐/音效生成、批量音效、素材导入、片段选择/裁切/分割/移动/变速/音量/循环/淡入淡出、轨道音量/静音/独奏和混音导出。

通用控件目录只暴露当前可见的 Foart 制作控件及其原有边界；切换面板、加载素材、打开对话框后重新观察。骨骼、人偶、片段、图层及素材均使用真实现存编号。目录接入不等于每一个参数组合都经过效果验收。

## 实际操作结果

| 路径 | 实际结果 |
| --- | --- |
| GPT 普通生图 → 连续改色 | 两个真实任务；红色机器人只改外壳为蓝色，第二次使用首次生成结果作为图生图输入 |
| 原生抠图 → PNG → 连续改画布 | 透明 PNG；1024→1200 居中扩画布，主体边界精确平移 88 像素，尺寸保留 |
| H3 四模式 | 各有新 MP4；352×352、56 帧、24 FPS；首尾帧实际绑定两张图，多参实际包含图/视频/音频引用 |
| 多参输出识别 | 当前激活资源编号来自新任务 bf4e256d，输出 SHA256 与参考片不同 |
| 视频时间轴 | 原片保留，裁切/变速/移动/画布变换后新资源 352×352、2.5 秒 |
| 帧编辑 | 原片 56 帧；原有镜像追加反向帧，新资源 111 帧、24 FPS，界面显示 4.6 秒，原片仍在 |
| 音效生成/连续编辑 | 实际 WAV；同一片段由 50%/3 次循环继续改成 25%/2 次循环，并得到不同长度导出 |
| 批量音效 | 两个真实任务、两个不同新 WAV，未重复触发额外批次 |
| 音乐/混音 | 实际音乐任务；循环按原有小节规则为 7.2 秒；轨道 60% 与独奏状态同步到实际控件 |
| 姿势参考 | 真实头部关节 X=15°，范围滑条和数值输入均为 15，未生图 |

任务编号、文件哈希、原生输出尺寸和验收限制见 [结构化回执](experiments/xiaotao-native-tools-20261030-receipt.json)。实际媒体和操作截图保存在本机 `work/xiaotao-all-tools-20261030`。

## 修复的实际问题

- 上传全量 base64 与全项目状态序列化导致界面卡顿；观察只保留需要的设置和素材身份，文件流沿用原生入口。
- 续改误路由到生图、旧参考再次覆盖当前编辑、原始素材冒充新输出、模型重复提交生成或重复导出。
- 工具回执与模型文字不一致；生成文件、模式、结果编号按原生回执验证，缺少结果不能报告制作完成。
- 历史 JSON 引号混入优化要求导致“台词丢失”误报；原有优化器仅接收真实用户要求，规划仍保留历史事实。
- 否定“不要导入剪辑”误取消正向帧编辑；资源异步加载与帧率初始化造成旧快照误拦截；原生加载现在有可等待的入口。
- 同一规划使用尚未启用的后续控件；先执行独立有效前缀，再观察新状态。
- 澄清回复提及现有输入文件时被误当成虚构输出过滤；原生姿势窗口遮挡聊天与截获聊天键盘事件。
- 本地多轮规划的耗时重新计数；改为本次任务累计计时。“生成后结束”和“打开后结束”由真实回执结束，省去额外规划。
- 本地测试入口的控制面配置与会话验证；有效登录无需因本地配对失败而被错误清空。

## 验收边界

未对所有美工增强、UI 设计、视频抠图/调色/蒙版的所有参数组合逐一完成 GPU 效果验收，不能声称全功能效果全过。视频导出已观察到原生编码回执及新资源，浏览器 blob 下载最终落盘未独立确认。H3 的两秒请求按原有规则输出约 2.333 秒。音乐循环按原有小节裁切，不保证与输入秒数完全相同。

在线简单生图提示词优化单次实测约 16 秒；本地冷规划单次约 48 秒，本地视频优化完整流程单次约 86 秒，均不是平均值。复杂请求的多轮规划和模型加载仍会增加等待，不能把制作耗时和提示词耗时混为一项。
