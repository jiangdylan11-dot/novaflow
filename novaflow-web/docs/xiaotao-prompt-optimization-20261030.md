# 小桃普通生图与视频提示词优化接入（2026-10-30）

> 后续更新：视频各模式的原规则接入及新旧素材别名已进一步修正；本报告中的小桃共用配乐、固定镜头收尾规则已移除，当前行为和逐模式验收见 [视频四模式接入记录](xiaotao-video-mode-integration-20261030.md)。

目标是更准确地保留用户意图并形成可执行的模型提示词，而不是增加篇幅。此次为本地智能接入，沿用现有文生图/单图编辑和音视执行能力；在线智能执行范围未扩展。源码和开发运行目录更新，未打包安装程序、未部署站点，统一版本仍为 2.0.169。

## 实现

- `__NovaFlowSmartAI.optimizeForAgent` 与原提示词优化弹窗共用请求构建、原始引用保护、优化器、质量规则及返回校验。纯文本使用原有语义融合；已有六段机器结构才启用 `nf.art.prompt.v1` 编译，避免把普通描述强制套成另一份模板。
- 小桃普通生图先形成完整草稿，再交原框架优化；校验通过才写入和提交原有工作流。普通草稿使用原优化器要求的中文，通过原校验后在同一所属 Flash 会话内仅翻译为英文执行版本；用户提示框及聊天显示中文，画面中文字保留原文。手动输入及原优化弹窗不启用这一小桃专属翻译。双图风格迁移继续使用原美术导演，不叠加普通生图重写。
- Qwen Image 2.1 区分文生图与编辑策略：保留数量、颜色、方位和文字；优先表达可见的材质、空间、光照。编辑只强化用户指定的改动，以保留条款约束其他内容，不重述未修改区域。
- 视频复用原 H3 工作流的参考帧采样、模式/时长、官方字段验证及执行编译；其他视频继续走原动画提示词优化器。优化失败、引用不全、官方编译降级均不提交生成。
- 方案绑定当前快照；优化期间参考图、参数或素材变化，或用户停止，结果不能迟到写入。生成前仍检查真实模型身份及所属会话的资源释放回执。
- 优化后的生图正向和负向提示词按本次校验结果应用；手动采样参数保留。任务记录同时保存原草稿和实际应用文本，用户反馈关联真实成图。

Qwen 适配参考了用户提供的 [qwen-image-2.1-skill](https://github.com/iamyoki/qwen-image-2.1-skill) 与 [Qwen 官方重写规则](https://github.com/QwenLM/Qwen-Image-2.1/tree/main/prompt_rewrite/prompts)，采用适合现有应用的规则，没有移入固定长篇字数或强制堆叠物件的要求。

## 验证边界

实际测试使用独立本地工作台、原应用入口、实际 Flash 与本机 Comfy 工作流，无伪造模型结果。对比样本使用相同 seed、画幅、Turbo 8 步和 CFG3。相关原始证据保存在忽略目录 `work/xiaotao-optimization-20261030/`，不提交授权信息或本机配置。

真实调用发现并修正两处对接问题：原优化会话返回的实际权重路径身份与原生工具的模型 ID 身份均为受支持的核验方式；普通生图草稿需要与原中文优化合同一致，不能用跨语言词面覆盖率判断保留情况。上述校验失败均在生成前拦截。实际出图还暴露了普通创建方案缺少结果登记元数据的问题，已补齐并确认新图片进入原有结果列表。

另恢复原技能服务依赖但遗漏的历史 `style-transfer.1.0.13.json`，内容与已有实验归档一致，不改变当前 1.0.14 技能。

## 实际生图验收

同一组请求直接生成原始样本，再经小桃优化生成：768×768、seed 3471123、Turbo 8 步、CFG3。要求米白底、左侧恰好两个红球、右侧一个蓝色立方体、底部居中黑色标题“春日计划”、平视、柔光、磨砂材质及大面积留白。

- 原始样本数量、左右位置和文字已正确；优化后这些硬约束全部保留，磨砂表面与柔和明暗表达更明确，没有新增物件。
- 最终新成图 `artgen_mvujgeej` 已进入原有应用结果列表，中文提示框与优化展示版本一致；实际 Qwen 编码节点收到完整英文执行版本，画面中文字仍为“春日计划”。
- 英文翻译沿用已经通过原框架校验的内容，不重新创作。此样例不支持“所有提示词都必然更好”的结论；模糊需求、复杂动作和生成模型本身的随机性仍需要用户反馈判断。
- 生图优化及翻译所属会话耗时约 71 秒，另有小桃方案调用和图片生成时间。准确性增强同时增加首轮等待；当前没有把两次模型加载合并为同一次会话。

自动验证覆盖 160 项 Node 测试、3 项 Python 策略测试；`sync:runtime`、`check:runtime`、`check:entry` 通过。新增覆盖原框架失败、未确认释放、未知身份、失去模型适配、优化期间上下文变化、中英文独立写入、执行版本篡改、英文翻译不改中文字、手动输入不触发翻译及任务记录不能事后改写。


## 视频效果反馈修正

首轮 H3 成品已证明中文展示和英文工作流内容对应，但出现红球部分出画，且优化结果自行加入钢琴配乐。不能把这次任务完成等同于效果完全通过。

小桃的 H3 请求因此加入两项按用户意图启用的执行要求：未要求配乐时使用 `N/A`；固定镜头内移动并停止时留足运动余量，让主体保持完整、以画面内短距离移动并在末段停住。明确要求出画、特写或配乐时不覆盖用户意图。短视频的静止收尾不强占整整一秒。相关覆盖已加入测试。

H3 原有流程先产出中文字段，再由原有 translate-only 编译返回中英文对应版本；编译结果进入原工作流的翻译缓存，原生提交复用同一份已校验英文，不再次创作。编译阶段同样检查资源释放，拒绝手动入口允许的 as-written 降级。

## 最终视频实测与限制

最终任务 `44bccc98-4bd8-4606-97ee-2783fd2a3e47` 实际生成 480×864、24 FPS、107 帧 MP4，文件 781,758 字节。请求 4 秒，原模型按帧对齐策略输出约 4.46 秒，本次不改变该时长策略。

逐项对照结果：

- 原生提示框为中文，最终 H3 编码图中含有与优化回执完全相同的英文；参考的实际 graph 并非仅检查 UI 字段。中文展示、英文编译和实际提交一致性通过。
- 画面保持单个红球和灰色环境，第二轮英文音乐字段为 `N/A`，不再自行补入钢琴。
- 末段完全停止、完整留在画框中、全程固定镜头三项**未稳定通过效果验收**：抽帧与红球轨迹显示短暂触边、末段回摆和背景漂移。提示词中已有停止和固定镜头要求，实际生成仍有偏差，不能把模型任务完成解释为画面完全符合要求。
- 本次没有更换用户选择的生成模型/模式或擅自增加首尾帧输入，也没有把失败样本删除后宣称所有效果通过。后续若需要更严格动作精度，应另行评估首尾帧/运动条件控制，而不是承诺只靠提示词可以保证。
