# 小桃视频四模式接入与实际验收（2026-10-30）

本次以当前可用的 MiniMax H3 本地入口为范围：文生、图生、首尾帧、多参。实际界面的模型选项只有该本地模型，旧云端 Kling/ByteDance 入口已经下线；不为下线模型套用通用优化规则，不声称完成不存在入口的付费云端生成。

## 规则与执行

| 模式 | 原始协议 | 原有参考约束 |
| --- | --- | --- |
| 文生 | T2VA，三字段 | 无输入参考，描述画面、动作、声音 |
| 图生 | I2VA，三字段 | 唯一图片绑定第 0 秒开场，优化器读取实际图片 |
| 首尾帧 | FL2VA，三字段 | 首尾图片分别绑定开场与结尾，保持独立身份、连续过渡 |
| 多参 | Ref2VA，六字段 | 主体定义、任务关系、保留规则、动作细节、环境声、配乐；图片/视频/音频按原引用角色处理 |

- 小桃继续调用原 `prepareRequest`、`validateAndRestore` 和 `compileForGeneration`，保留各模式原有采样、格式、引用验证及翻译缓存。没有重写一套共同视频提示词模板。
- 移除上一轮小桃新增的“未提配乐则 N/A”和统一的固定镜头收尾规则。多参原有音频复用、音频参考及其配乐规则不再被这些额外默认项覆盖；具体音乐需求仍由用户与各模式原框架决定。
- 小桃读取当前模式的原始字段协议、实际上传素材的中文标签、模型编号、来源 ID 和类型。图片外观、视频动作/编辑/续写、音频复用/参考互相独立；不能凭文件名声称听懂音频。
- 修正原提示词编译器与当前素材组件之间的新旧别名兼容：`@参考视频 1` / `@参考音频 1` 与旧名称映射到同一素材。用户补充要求也通过原引用目录编译，未上传编号不能冒充有效资源。
- 优化器读取参考图片，视频走原九帧采样。实际生成仍上传原图片、完整视频和音频文件，不把采样图片当成生成时的视频文件。
- 音频完整复用继续走原 `fully_copy` / `TrimAudioDuration` 路径；音频参考保留模型音频解码路径。两种路径均有实际工作流构建测试。

## 实测中修复的资源交接问题

首轮多参成功后，下一次加载因 Windows 将已退出的 `nvidia-smi.exe` 的 PID 复用于实际 Strata 引擎而触发旧进程身份锁。修复仅允许退役已证明退出的短命 GPU 检测/控制台辅助进程身份；新进程仍须从已独立验证的 HTTP 父进程树中重新观察、记录并在发信号前核验。HTTP 或模型/视觉进程自身身份变化、未知子进程及无法核验的身份仍失败关闭。没有直接按 PID 杀进程或绕开资源释放检查。

49 项 CPU 生命周期测试通过，包含：辅助 PID 复用后重新记录真实所属引擎、外部进程复用辅助 PID 时不被接管或发信号，以及原有主进程/重型子进程 PID 复用拒绝测试。实际故障会话通过原所属会话清理接口恢复为 `released` 后继续验收。

## 验收证据与边界

使用独立本地工作台、实际本机授权、实际 Flash 与 H3 工作流。证据位于 `work/xiaotao-video-modes-20261030/`；没有伪造模型/视频结果。首轮交接失败、资源余量中止及素材未完成加载导致快照失效的记录保留，后续重测等待原上传完成，不取消素材变化防护。

多参实测已经确认：

- 六字段 Ref2VA；优化请求包含 1 张图片与参考视频的 9 个真实采样帧。
- 最终 `MiniMaxH3ReferenceToVideo` 的图片、视频、音频来源 ID 与上传记录一致，三个 `Load*` 节点对应原文件 SHA-256 全部一致。
- 模型收到的完整英文与本次优化回执逐字一致；界面将旧引用名称归一到当前中文标签后，中文展示稿内容一致。
- 完整复用音频实际采用原轨而非生成音频解码。解码至 24 kHz 后，与源音频相关系数 0.999970、增益 0.998602、相对 RMS 误差 0.007868，差异与 MP4/AAC 有损编码相符。
- 单红球及向右运动可见；输入图片与参考视频来自同一灰色红球场景，该样例不足以证明复杂外观/背景/动作分离都已稳定。不会把真实文件绑定通过解释成所有视觉细节均遵循。

本次更新源码和开发运行目录，未打包安装程序、未部署网站。前一轮报告中的视频效果限制仍应按具体实测结果看待。

## 最终四模式验收

| 模式 | 原协议与素材 | 实际输出／可见结果 |
| --- | --- | --- |
| 文生 | T2VA，0 参考帧 | 已生成；单个蓝色立方体转动，蓝色与数量保持 |
| 图生 | I2VA，1 参考帧 | 已生成；实际首帧文件 SHA-256 与输入一致；开场与参考图 SSIM 约 0.97386 |
| 首尾帧 | FL2VA，2 参考帧 | 已生成；首尾文件分别接到 `first_frame` / `last_frame`，两端 SSIM 约 0.97456 / 0.97417 |
| 多参 | Ref2VA，1 图＋1 视频＋1 音频 | 已生成并完成最终交付核对；三类原文件与真实加载文件的 SHA-256 全部一致，原轨复用成立 |

四项均核对了：本次完整英文在实际 Comfy 编码节点中逐字存在；中文展示经原引用目录归一后内容一致；界面回执文件字节与真实 SaveVideo 输出一致。四项不是只调用接口或只运行静态检查。

### 输入预览误作生成结果的修复

最后核对发现，Comfy 的 `LoadVideo` 会在 history 中返回 `type: input` 的参考视频预览。原公共输出收集器把它也复制进任务输出清单，界面因此可能最终拿到原参考片。已在实际边界修复：明确为 `input` 的图片、视频、音频预览不再作为生成输出；正常输出和原有临时生成结果保持原行为。新增回归测试覆盖三种输入预览。

修复后通过小桃重新走了一次完整多参生成，最终界面回执文件：

- `Video_00015_-3bf10e74-1.mp4`，201,720 字节。
- 该文件、任务输出副本、真正 SaveVideo 输出的 SHA-256 均为 `fb92b2b41acc1be81383bd8f66adf8c7cd8247800d098cfc6bbf4a611f661030`。
- 原参考视频为 257,163 字节，SHA-256 为 `495eb53cde0132d7426f30f443cafadd0278ac6a002424c531ee7eb97f41357e`，与界面收到的文件不同。
- 任务输出清单仅一份生成视频；完整复用音轨再次测得相关系数 0.999970、增益 0.998602，符合源音频经 AAC 编码后的差异。

### 效果限制与未覆盖范围

- 请求均为 4 秒，当前原 H3 帧对齐策略输出 107 帧、24 FPS，约 4.46 秒；本次未改动该策略，不能声称精确为 4.00 秒。
- 图生样例末段有约 18 像素的小幅回摆，单向运动的逐帧精度没有完全通过。
- 首尾帧 SSIM 约 0.974 表明端点接近输入，仍有生成／编码差异，并非逐像素复制。
- 多参使用的图片与视频来自同一红球场景，能够验证真实文件、编号和音轨复用，但不能据此证明复杂的身份、背景、动作分离全部稳定。主体部分触边也未被掩盖。
- 真实多参样例为三类素材各一份；9 图／3 视频／3 音频上限、编号重排及持久化属于传输契约测试，不等同于最大规模 GPU 效果验收。音频“仅参考”与“完整复用”的区别通过真实工作流构建检查，本次 GPU 音频样例是完整复用。
