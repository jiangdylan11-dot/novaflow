# 自动骨骼权重 测试线（autoskin-bench）

把美术做好的 Spine 3.8 工程当作参照：丢掉它的全部权重，用 `particle-editor/spine-auto-weights.js`
重新绑定，再和美术原版逐帧对比。全部在 Node 里跑，姿态用仓库自带的官方
Spine 3.8 运行时（`particle-editor/vendor/spine/spine-webgl-3.8.js`）无头计算，IK、变换约束、FFD 都算在内。

## 跑法

```bash
cd tools/autoskin-bench
node build-rig.cjs 22                     # 生成 out/rig{A,B,B2,B3,C}.json、artist*.json、build.json（选骨精度/召回）
node deform-error.cjs rigA                # A 方案逐顶点形变误差（px）
node metrics.cjs artist,rigA,rigB2,rigC 0.2   # 逐帧轮廓 IoU（整体 + 每层）
node figures.cjs artist,rigA,rigC,rigB2 0.6,1.0,1.4   # 并排帧、差异图、躯干放大、权重热力图
node mech-render.cjs                      # 机构骨（不参与权重）标红
node sweep.cjs                            # 权重求解参数扫描
node render.cjs out/rigB2.json out/b2 0,0.5,1 --bones   # 任意 rig 渲染
node variants.cjs                         # 一批选骨规则变体：构建 + IoU，出表
node video.cjs artist,rigB2,rigA 30 0.5   # 并排视频 out/compare_full.mp4 / compare_zoom.mp4（30fps，循环两遍，ffmpeg 用 node_modules/ffmpeg-static）
node errmap.cjs                           # A 方案误差最大的层：最差帧上美术顶点(绿)→自动顶点(红) 的位移图 + 最差顶点两套权重
```

诊断脚本：`select-study.cjs`（几何选骨规则对比）、`assign-study.cjs`（独占分配规则对比）、
`bone-usage.cjs`（选错的骨在美术工程里归谁）、`fit-probe.cjs` / `fallback-probe.cjs`（小层候选骨贴合度）、
`analyze-bind.cjs`（绑定坐标复现偏差）。

## 2026-09-20 结果（伽夜立绘，密度 22）

| | 整体 IoU | 最差帧 | 选骨 P / R |
| --- | --- | --- | --- |
| A 美术网格 + 美术选骨 + 自动权重 | 0.979 | 0.971 | - |
| C 自动网格 + 美术选骨 + 自动权重 | 0.978 | 0.971 | - |
| B2 全自动 | 0.972 | 0.961 | 0.930 / 0.826 |
| B 旧选骨 | 0.882 | 0.832 | 0.600 / 0.777 |

A 方案逐顶点误差：21 帧平均 1.5 px（按层平均）/ 2.2 px（按顶点平均），最大 40 px。

**脸（点控制骨）**：美术的规则是同层有线段骨时，零长度控制骨只拿部分权重（脸 0.4~0.63、胸部 0.8），
全层没有线段骨时才独占（胸罩、花朵）。求解器按此把控制骨最近处的热源拆成 `pointPeak`（默认 0.6）给控制骨、
其余给最近的线段骨；脸的误差 2.10 → 1.38 px，脸 IoU 三个方案都到 0.971。选骨上点控制骨归"包含它的最小图层"，
父骨（头骨）在层内更近的顶点占比 ≥ 0.4 时一并带上（脸 0.50 加、胸罩 0.30 不加），贴着图层边缘（<4 px）跑的骨不算该层的骨。

`errmap.cjs` 定位到的 A 方案剩余差异，都是美术的绑定意图而不是算法误差：
- body / zhuangshi / xianlian：美术给轮廓外 200 px 处的零长度控制骨 `bone` 分了 0.1~0.25 权重（胸部摆动控制器），热扩散对轮廓外的点骨永远给 0；
- bu3：美术把布片顶点直接绑到腿部 IK 目标 `leg1`（0.96~1.0），让布跟脚走；
- hair_back：美术把整段发梢固定为 bone96:0.62 / bone97:0.38，热扩散沿链平滑过渡（发尖差 20 px）。

B2 相对 C 的差距集中在几何判不出的归属：胸部四个点控制器（bone35/36 归 body、bone102/103 归 xiongzhao）、
脸的头骨 bone14（比脸图层大，被 hair_back 完整包含）、头饰绑 50 px 外的头骨（fashi2）、多层共享的躯干锚骨（bone2/3/6/11/26）。
这些交给每层骨骼勾选表由用户改。

`export-reskin.cjs` 会把 rig 打包成 NovaFlow 导入工程能直接吃的 JSON + atlas + images（`out/reskin/`）。

## 2026-09-20 夜：权重编辑器（手工修正）已接入应用

用户结论：精细处无法全自动，需要 Spine 式的手工刷子。已落地：
- `particle-editor/spine-auto-weights.editor.js`（`NovaFlowAutoWeightsEditor.open(imageData, mesh, {bones, boneIds, weights, auto})`）：
  骨骼列表（色块、合计、× 移除、+ 添加）、直接/叠加/平滑三种笔刷、权重与半径滑条、饼图/叠加显示、自动/平滑/修剪、撤销/重置，
  每个顶点权重之和恒为 1；几何半边在 `_internals` 里可无头测试。
- 面板 `spine-auto-mesh.panel.js`：新增「自动权重」总按钮（勾选层：逻辑层级 + 双锚定分配 → 热扩散 → 写回）和每层「权重」按钮；
  已是网格的附件直接沿用其顶点和已有权重（fromMesh）；网格重算/编辑后按原骨骼集自动重解；
  骨骼矩阵来自应用当前的官方播放器（钩住 `__NOVA_SPINE_CREATE_PLAYER` 记住实例，用它的运行时命名空间和 SkeletonData 摆一个绑定姿态骨架），
  无播放器时退回纯骨骼树。
- 求解器新增 `setupPoseMatrices / matricesFromRuntime / attachmentWorld / weightsOfAttachment / applyWeights`。
- 预览实测（4786）：导入导出包 → 自动权重 7 层写回 → 打开 faec 权重编辑器涂抹/撤销 → 完成写回 → 角色照常渲染。
  教训：导出包若保留了备用皮肤里没有图片的附件，官方运行时会整体报 `Region not found in atlas` 并回退到画不了加权网格的旧预览（画面空白），
  `export-reskin.cjs` 现在会剔除这类附件；写回时 `bridge.start()` 在预览面板隐藏时不会完成，要让面板可见。

## 2026-09-20 深夜：脸部五官（用户复审「五官扭曲」）

轮廓 IoU 对脸内部完全不敏感（脸 0.983 时五官仍在扭曲），全脸像素均值误差也会偏爱"大而软的糊块"；
判断脸要看 `weights-map.cjs`（逐控制骨权重图）和 `face-probe.cjs`（眨眼帧 3 倍特写，时刻用 `blink-times.cjs` 找）。

- 权重图揭示的根因：美术的每个眼睑控制点只占一小块贴合眼睑的补丁（12~20 顶点，峰值 0.5~1.0，眼睑随控制点整体滑动做眨眼），
  头骨全脸接近 1.0；而 Voronoi 拆分把控制点铺到整个最近区域（eyes_l_up 93 顶点、半张脸），控制点一动半边脸颊跟着动。
- 求解器新增：控制点影响半径 `pointRadius`（默认 0.12×图层对角线，脸和胸部点的美术数据都在这个比例）；半径内可选平台钉扎 `pointPin`（相对拉普拉斯对角线）；
  逐控制点覆盖 `radiusFrac/radiusPx/peak/pin`（写在骨段对象上）；可选边缘门控 `featureGate`+`gate/gateMin`。
- 美术对眼睑和嘴用的是相反策略：眼睑紧、强、刚性（补丁整体滑动），嘴宽、弱、软（0.2~0.3、25~55 顶点），
  几何上分不出，但工程里的骨名分得出。测试线按骨名加载预设（`extra.presets`，默认 eye|lid → 半径 0.08、峰 0.85、钉 5；
  mouth|lip → 半径 0.16、峰 0.3、软）。眨眼帧特写：眼睛能眯下去、嘴角不再折痕。产品里应做成"控制点类型"下拉（眼睑/嘴/转面/自定义）。
- 试过并否掉：全局平台圆盘（嘴角折痕）、边缘门控（上眼睑/上唇有效但下眼睑与虹膜边缘分不开，脸只有 103×116 像素）、
  结构线链补丁（眼周轮廓是一条 70px 的合并链，眼睑与虹膜同链）。
- 剩余：眼睑补丁的精确形状（沿眼睑而不是以眼角为中心的圆盘）只能手工微调，建议在网格编辑器里加"控制点补丁"刷子。

## 2026-09-20 晚：切到优化版工程后追加的规则

- **逻辑层级**（`logicalParents`）：Spine 里小腿挂在大腿的 IK 目标下、脚挂在小腿的 IK 目标下（脚要踩实），树上并不相连。
  把 IK 目标的子骨视为该 IK 链末端骨的子骨，大腿→小腿→脚重新成为一条链，髋骨成为腿链/裙链的逻辑父骨。
  leg_1 0.915 → 0.935，skirt 0.912 → 0.929。
- **双锚定**（`anchors:'both'`，默认）：链头把它挂着的父骨带上（腿带髋、裙条带髋、花带上臂）+ 点控制骨的父骨（脸带头骨）。
  hua1 0.75 → 0.92，leg_2 0.975 → 0.981，召回 0.842 → 0.888。覆盖补骨（`cover`）再次验证有害（arm_l 0.98 → 0.80）。
- **turn 类控制器**（face_turn / body_up_turn / body_down_turn / face_turn_back）：用户说明是整体转面做伪 3D 的控制器，
  美术给的是整层均匀弱权重（脸 0.15、身体 0.06、腿 0.02）。几何上和眼睛控制点无法区分；参与自动求解只会得到一个错误的局部块，
  排除后 A 方案误差 1.51 → 0.98px（双腿 0.6px）。默认不动它们（IoU 无差别），`{"skipNames":"turn"}` 可按名称排除，产品里应由用户指定"整层统一百分比"。
- **对比基准**：自动网格按美术工程每层实际的 uv→世界仿射映射摆放（`fitAffine`），而不是 PS 摆放。
  工程里 leg_1 声明宽 961 而图 958 宽，美术画面比 PS 摆放偏右 1.5px，静止姿态 C 就掉到 0.954、整条腿边缘一圈红青；这是摆放不是蒙皮。`{"psPlacement":true}` 可切回。
- `layer-diff.cjs <layer> [rigs] [times] [--mesh]`：单层独立渲染 + 差异图 + 网格线，定位某一层的 IoU 损失来自哪里。
- 已知无解的剩余项：被删图层留下的骨链（bu3 的 y2~y11 被分给裙子、xiongzhao 的 bra_l/bra_r 被分给身体）——产品里删图层时应连骨一起删，或在勾选表里去掉。
